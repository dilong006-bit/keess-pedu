## 1. 요구사항 (사업 확정)

> **마감을 제외하지 않는다. 모집 상태 「마감」을 선택했을 때 어떤 과정의 어떤 일정이 마감인지 사용자가 빠르고 쉽게 파악할 수 있어야 한다.**

### 1-1. 현재 상태 (2026-09-08 배포본 실측)

모집 상태 `마감 1` 선택 시 화면:

| 영역 | 현재 표시 | 판정 |
| --- | --- | --- |
| 모드 헤더 | `공개교육 일정 · 10~12월 · 마감 1개 회차` | 정상 |
| 일정 박스 본문 | `해당 조건에 신청 가능한 회차가 없습니다. 전체 일정에서 지난 회차를 확인하실 수 있습니다.` | **결함** |
| 전체 일정 리스트 | 마감 행 1건 존재하나 **토글을 눌러야 열림** | **결함** |
| 과정 카드 회차 레이어 | `11.18~19 모집중` (마감을 골랐는데 모집중 회차를 표기) | **결함** |

**세 지점 모두 "마감을 고른 사용자에게 마감을 보여주지 않는다."** 헤더는 1건이라 말하고 본문은 없다고 말하며, 카드는 다른 회차를 말한다.

### 1-2. 해결 방향 (F21 채택 근거와 충돌 없음)

F21은 스트립에서 `closed`를 제외하는 규칙(F0-9)을 유지하되 확인 경로를 「전체 일정」 리스트와 상세 패널로 지정했다. 본 명세는 **그 규칙을 건드리지 않는다.** 대신 **스트립이 0장이 되는 순간 같은 자리를 리스트가 대신하도록** 하여, 사용자가 토글을 찾지 않아도 결과를 즉시 보게 한다.

| 접근 | 판정 |
| --- | --- |
| 스트립에 마감 카드를 섞어 넣는다 | **기각**. 스트립은 「다가오는 신청 가능 일정」 표면이다(F21 채택 근거 2). 성격이 흐려지고 10월 중순 이후 자동 승격으로 마감이 늘면 티저가 마감으로 뒤덮인다 |
| 안내 문구에 「전체 일정을 눌러 보세요」를 넣는다 | **기각**. 결과를 보여주는 대신 조작을 한 번 더 요구한다 |
| **스트립 0장이면 그 자리에 리스트를 렌더한다** | **채택**. 스트립 규칙 무변경, 클릭 0회, 마감이 여러 건이 되는 오픈 후에도 세로 리스트가 조망에 유리 |

## 3. 변경 명세

### F24 (핵심) 일정 박스 본문 폴백: 스트립 0장이면 같은 자리에 리스트

`.kium-schedbox-body`의 렌더 분기를 **2분기에서 3분기로** 바꾼다.

| 조건 | 현재 | **변경 후** |
| --- | --- | --- |
| `visible.length === 0` | 빈 상태 문구 | 빈 상태 문구 (F26에서 문구 교정) |
| `visible.length > 0 && stripItems.length === 0` | **빈 상태 문구** | **`.kium-slist` 렌더 (자동 전개)** |
| `stripItems.length > 0` | 스트립 | 스트립 (무변경) |

- `stripItems` = 기존 스트립 소스(G4 규칙 그대로, `closed` 제외). **이 규칙은 건드리지 않는다.**
- 폴백으로 렌더하는 리스트는 **「전체 일정」 전개에서 쓰는 `.kium-slist`를 그대로 재사용**한다. 신규 컴포넌트·신규 마크업 금지.
- 폴백 리스트의 데이터는 **현재 필터가 적용된 `visible`** 이다. 전체 일정(필터 무시 전량)이 아니다.
- 폴백 상태에서 `.kium-schedbox-toggle`(전체 일정 토글)은 **계속 노출**한다. 라벨·카운트는 기존 규칙 유지. 이미 리스트가 보이는 상태에서 토글을 누르면 필터를 무시한 전체 일정으로 전환되며, 재클릭 시 폴백 리스트로 복귀한다.
- 폴백 진입 시 `aria-live="polite"`로 안내: `조건에 맞는 회차 {n}건을 일정 목록으로 표시했습니다`
- 등장 트랜지션은 스트립과 동일 토큰(200ms 페이드) 재사용. `prefers-reduced-motion: reduce` 시 생략.

**적용 결과 (마감 1 선택 시)**

```
공개교육 일정 · 10~12월 · 마감 1개 회차        전체 일정 1개 회차 ▾
──────────────────────────────────────────────────────────────
10.21(수) ~ 22(목) · 2일   리더십·관리자
진단 기반 팀장 리더십 Re-Lead 과정   14시간   400,000원   [마감]  다음 회차 상담 →
```

### F25 과정 카드 회차 레이어를 필터 결과 기준으로 표기

- 현재: 필터와 무관하게 최근접 **신청 가능** 회차 1건 표기(G7). 마감을 고른 사용자에게 `11.18~19 모집중`이 보인다.
- 변경: **현재 필터가 적용된 `visible` 중** 해당 과정의 회차를 대상으로, 아래 우선순위로 1건을 표기한다.

| 순위 | 대상 |
| --- | --- |
| 1 | `visible` 내 해당 과정의 회차 중 신청 가능(closed 아님) 회차 중 가장 이른 회차 |
| 2 | 1이 없으면 `visible` 내 해당 과정의 회차 중 가장 이른 회차 (마감 포함) |

- 마감 회차를 표기할 때 뱃지는 기존 `마감` SessionBadge 규격, 행 전체에 `data-status="closed"` 부여(G11 저채도 규칙 자동 적용)
- 회차 레이어 표기 대상이 2건 이상이면 날짜 뒤에 ` 외 {n}건` 병기. 1건이면 미표기
- 필터 `전체` 상태의 표기 결과는 **현행과 동일해야 한다**(회귀 기준)

### F26 빈 상태 문구 교정

`.kium-noses.kium-ustrip-none` 문구를 교체한다.

```
현행: 해당 조건에 신청 가능한 회차가 없습니다. 전체 일정에서 지난 회차를 확인하실 수 있습니다.
변경: 해당 조건의 회차가 없습니다.
```

- `지난 회차` 표현은 **사실과 다르다**. `relead-r1`(10.21~22)은 아직 오지 않은 날짜이며 정원 충족 마감이다(F21 3-1). 코드 내 `지난 회차` grep 0건이어야 한다.
- 문구 아래 **[필터 초기화]** 버튼을 추가한다. 기존 `resetFilters()`에 연결하고 기존 버튼 토큰을 재사용한다(신규 색 토큰 0).
- F24 적용 후 이 빈 상태는 `visible.length === 0`에서만 노출되므로, 실질적으로 **`?preview` Empty Case 칩(F23) 전용 화면**이 된다. F23 검증 항목 E4의 기대 문구(`해당 조건의 회차가 없습니다.` + `필터 초기화`)와 이로써 일치한다.

- F22(0건 칩 미노출) 규칙과 선택 칩 자동 해제 `useEffect` 무변경
- F23 `?preview` 게이트 · `Empty Case` 칩 · `.kium-chip-review` 무변경
- 프리필 문안 2종(경로 A, 마감 가드 G6), 관심 영역 자동 선택, 확인 배너 무변경
- 모드 헤더 문구·세그먼트 라벨·카운트(`전체과정 19` / `공개교육 9`) 무변경

- 교육비 노출 분기(공개교육 개설 과정만) 무변경
