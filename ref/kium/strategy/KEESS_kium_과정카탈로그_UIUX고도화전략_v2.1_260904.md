### 1-2. ★ Re-Lead 12월 회차 — 제 앞선 판단이 틀렸습니다

**v2.0에서의 판단(오류)**

> 원문 `12/17(수)~18(금)`은 요일도 틀리고 2일 과정인데 수~금 3일 폭이라 **일자 자체가 미확정**이다 → 배열에서 제외

**재분석**

| 항목 | 값 | 판정 |
| --- | --- | --- |
| 원문 표기 | `12/17(수)~18(금)` | |
| **날짜 숫자** | 17 ~ 18 = **2일** | ✅ **정합** — 이 과정은 14시간·2일 |
| 요일 라벨 | 12/17을 (수)로 표기. 실제 2026-12-17은 **목요일** | ❌ **오기 1건** |
| 12/18 요일 | (금) — 실제 금요일 | ✅ 정합 |

**오류는 요일 라벨 `(수)` 하나뿐이고, 날짜는 문제가 없습니다.** 제가 "수→금 3일"이라고 본 것은 **틀린 요일 라벨을 기준으로 폭을 계산한 것**이었습니다. 날짜 17~18은 명백히 2일이고 과정 길이와 일치합니다.

**그리고 이 시스템은 요일을 저장하지 않습니다.**

```ts
// lib/kium/sessions.ts — 요일은 전부 start에서 파생한다
const DOW = ['일','월','화','수','목','금','토'];
```

즉 **날짜만 넣으면 요일은 시스템이 자동으로 바로잡습니다.** 원문의 `(수)` 오기는 화면에 재현되지 않고 `12.17(목) ~ 18(금)`으로 출력됩니다. 이것이 v1.1 명세에서 "요일을 데이터에 저장하지 않는다"고 정한 설계가 실제로 값을 하는 지점입니다.

**확정**

```ts
// 주석 해제 + 일자 확정
{ id: 'relead-r3', courseId: 'kium-04', displayMonth: 12,
  start: '2026-12-17', end: '2026-12-18', status: 'recruiting' },
```

- 화면 출력: `12.17(목) ~ 18(금)` · 2일
- On-Powering `onpow-r2`(12/16~17)와 12/17이 겹치지만 **다른 과정이므로 문제없음**
- 사업부 확인은 여전히 받되(§10 D6), **데이터는 넣어서 20회차를 성립시킨다.** 원문 날짜를 신뢰하고 요일만 교정하는 것이 원문 존중과 정확성을 모두 만족한다

### 1-4. `displayMonth` 재확인 — 11/30 회차

`agent-r3`는 **11월 30일에 시작해 12월 열에 배치**된다(사업부 원안). 정렬·과거 판정은 `start`, 월 필터는 `displayMonth`를 쓴다. **현행 코드가 이미 이 규칙대로 동작함을 확인했다**(`countByMonth`가 `displayMonth` 기준).

첨부 화면의 `10월 6 / 11월 6 / 12월 7`도 이 규칙과 일치한다(20건 복원 시 12월 8).

## 2. 화면 카운트 오류 3건 ★

첨부 화면(필터 바)에서 확인된 문제다.

### 2-1. 세그먼트 「공개교육 일정 **19**」 — 좌우 단위 불일치 🔴

```tsx
// KiumCoursesTab.tsx:317, 326
전체 과정 <span className="cnt">{allCourses.length}</span>      // 19 = 과정 수
공개교육 일정 <span className="cnt">{future.length}</span>       // 19 = 회차 수 (우연히 같음)
```

| 문제 | 설명 |
| --- | --- |
| 단위 불일치 | 왼쪽은 **과정 수**, 오른쪽은 **회차 수**. 같은 세그먼트에서 서로 다른 것을 센다 |
| 우연한 동수 | 공교롭게 둘 다 19라 **"공개교육도 19개 과정"으로 읽힌다.** 실제는 9과정 |
| 즉시 모순 | 바로 아래 `분야 전체 9`, 그 아래 `5개 과정`과 어긋난다 |

**확정**: 세그먼트는 **보기 범위를 고르는 컨트롤**이므로 양쪽 모두 **과정 수**를 센다.

```
[ 전체 과정 19 ]  [ 공개교육 9 ]
```

회차 수(20)는 세그먼트가 아니라 **섹션 헤더**가 말한다(§2-4).

### 2-2. 기간 「전체 **19**」 — 20이어야 한다

`relead-r3` 복원으로 자동 해소된다(§1-2). 복원 후: `전체 20회차 / 10월 6회차 / 11월 6회차 / 12월 8회차`.

### 2-3. ★ 상태 시드가 미래 회차를 「마감」으로 노출한다 🔴

화면의 `모집 상태 · 마감 1`(12월 필터)이 이 문제다.

```ts
{ id: 'agent-r3', ... start: '2026-11-30', status: 'closed' },   // ← 미래 회차인데 마감
{ id: 'aijob-r1', ... start: '2026-10-19', status: 'closed' },   // ← 미래 회차인데 마감
```

`sessions.ts` 주석이 밝히듯 이 값들은 **4종 배지 UI를 화면에서 검증하기 위한 시드**이며 원문 근거가 없다. 개발 검증에는 필요했지만 **오픈 배포본에 남으면 안 된다.**

| 위험 | 내용 |
| --- | --- |
| 매출 손실 | 11/30 개강 회차가 9월 시점에 **마감**으로 보인다. 신청 가능한 회차를 스스로 닫는다 |
| 신뢰 | 이후 상태를 바로잡으면 "마감이라더니 열렸다"가 되어 일정 안내 전체의 신뢰가 흔들린다 |
| 자동 승격과 충돌 | `effectiveStatus()`는 **과거를 마감으로 올리는** 안전장치일 뿐, 잘못 박힌 `closed`를 되돌리지 못한다 |

**확정 — 2단계**

| 단계 | 조치 |
| --- | --- |
| **즉시(오픈 전 필수)** | `agent-r3`·`aijob-r1`·`agent-r2`(closing)·`cs-r1`(closing)·`data-r1`·`nego-r1`(confirmed) 등 **시드 값 전건을 사업부 회신값으로 교체**. 회신 전이면 **전건 `'recruiting'`**으로 초기화 |
| 근거 | 미확정 상태에서 가장 안전한 기본값은 `모집중`이다. 실제보다 **열려 있다고 말하는 쪽**의 손실이, 열린 회차를 닫아 보이는 쪽의 손실보다 작다(상담에서 회수 가능) |
| 배지 검증 | 4종 UI 검증은 `BadgeShowcase.tsx`(이미 존재)로 하고, **운영 데이터로는 하지 않는다** |

### 2-4. 섹션 헤더가 필터 상태를 반영하지 못한다

화면: `공개교육 일정  10~12월 6개 회차` — **12월 + 모집중** 필터가 걸린 상태인데 범위 문구는 `10~12월`이다.

**확정**

| 필터 상태 | 헤더 |
| --- | --- |
| 미적용 | `공개교육 일정 · 10~12월 20개 회차` |
| 월 선택 | `공개교육 일정 · 12월 8개 회차` |
| 월 + 상태 | `공개교육 일정 · 12월 · 모집중 6개 회차` |

범위 문구를 **필터에서 파생**시킨다. 하드코딩된 `10~12월` 제거.

## 3. 라벨 체계 — 「공개교육」으로 통일

### 3-1. 상세 패널 메타 pill

첨부 화면(상세 패널)의 현행:

```
[교육 대상 1~5년차 사원] [교육 형태 대면·실시간 비대면] [교육 시간 14시간·2일]
[정원 30명] [교육 일정 12.9(수)~10(목), 12.16(수)~17(목)] [교육비 400,000원 1인 기준]
```

`교육 일정`은 **이 과정 전체의 일정**으로 읽힌다. 실제로는 **공개교육 회차만** 나열한 것이고, 이 과정은 기업 위탁으로도 운영된다(위탁은 연중상시). **라벨이 사실과 다르게 읽히는 문제**다.

**확정**

| 현행 | 개선 | 사유 |
| --- | --- | --- |
| `교육 일정` | **`공개교육`** | 4자로 기존 라벨(`교육 대상`·`교육 시간`) 리듬과 맞고, 이 일정의 성격을 정확히 규정 |
| `교육비` | **`교육비`** 유지 + 각주 `1인 기준` 유지 | 라벨을 `공개교육 교육비`로 늘리면 장황하다 |

**시각 처리**: 공개교육 전용 pill 2종(`공개교육`·`교육비`)에 `data-open` 속성을 주고, `.kium-badge.open`과 같은 계열의 은은한 배경을 입힌다. 위탁 공통 정보(대상·형태·시간·정원)와 **한눈에 구분**되게 한다. 신규 색 토큰은 만들지 않는다(`--p3` 파생 `color-mix`).

### 3-2. 세그먼트 라벨

| 현행 | 개선 |
| --- | --- |
| `공개교육 일정 19` | **`공개교육 9`** |

`일정`을 뺀다. 세그먼트가 고르는 것은 일정이 아니라 **과정 범위**다. 일정은 그 안의 섹션이 보여준다.

### 3-3. ★ 표기 통일 — 「공개교육」 붙여쓰기

요청 메시지에 `공개 교육`(띄어쓰기)과 `공개교육`(붙여쓰기)이 함께 쓰였다. **표기를 하나로 정해야 한다.**

| 표기 | 근거 |
| --- | --- |
| **`공개교육` (권장)** | 요청 원문 PDF · 사업부 제공 FAQ 2문항 · 현행 코드·CSS 클래스(`kium-openlead`) · 기존 명세서 전부가 붙여쓰기다. **이미 사이트 전역에 쓰인 표기를 바꾸면 FAQ 원문까지 손대야 한다** |
| `공개 교육` | 국어 규범상 원칙이나, 교육 업계에서는 `공개교육`이 한 단어처럼 굳어진 용어다 |

**확정: `공개교육` 붙여쓰기로 전건 통일.** 화면·문서·코드 주석 모두. (§10 D7 확인 항목)

| 항목 | 내용 |
| --- | --- |

## 7. 기간 필터 숫자 — 오독 제거 *(v2.0 승계)*

### 7-1. 문제의 성격은 '모호함'이 아니라 '오독'이다

```tsx
{m}월 <span className="cnt">{monthCount(m)}</span>   // → "10월 6"
```

> **필터 행 라벨이 「기간」이다.** 기간 옆 숫자는 **일수(日數)로 읽힌다.**
> `10월 6` → "6일짜리 과정" 또는 "10월 6일"

실제 값은 **회차 수**다. **모르는 것보다 틀리게 아는 것이 나쁘다.**

### 7-2. 축마다 카운트의 성격이 다르다

| 축 | 예시 | 오독 위험 | 카운트 효용 |
| --- | --- | --- | --- |
| 분야 | `AI활용 3` | 낮음 | **높음** — 0건 회피 |
| 모집 상태 | `모집중 12` | 낮음 | **높음** — 결정 직결 |
| **기간** | `10월 6` | **높음** | 중간 — 선택지 3개라 어차피 다 본다 |

**일괄 처리하면 안 된다.** 세 축에 전부 단위를 붙이면 칩 폭이 커져 모바일 필터 바가 3줄이 된다.

### 7-3. 확정

| 칩 | 현행 | 개선 |
| --- | --- | --- |
| 기간 · 전체 | `전체 19` | **`전체 20회차`** |
| 기간 · 월 | `10월 6` | **`10월 6회차`** · `11월 6회차` · `12월 8회차` |
| 분야 | `AI활용 3` | 유지 |
| 모집 상태 | `모집중 12` | 유지 |

**접근성**: 전 칩에 `aria-label={`${m}월, ${monthCount(m)}개 회차`}`.

**반응형**: 기간 칩은 4개뿐이라 `6회차` 3글자를 더해도 375px 2줄 이내. 분야 칩 8개에 단위를 붙이지 않는 이유가 여기에도 있다.

### 7-4. 숨어 있는 자산을 살린다

`KiumCoursesTab.tsx:331`의 `aria-live` 결과 문구가 **`.kium-sr`로 숨겨져** 있다. 스크린리더 사용자만 듣고 **눈으로 보는 사용자는 못 본다.** 필터 바 하단에 시각적으로도 노출한다.

> `12월 · 모집중 · 6개 회차`

## 8. 캘린더 보기 — 보류(P2), 대안 2종 *(v2.0 승계)*

### 8-1. 데이터로 판단한다

| 지표 | 값 |
| --- | --- |
| 기간 | 92일 |
| 회차 | **20건** |
| 개강일이 있는 날 | 20일 = **21.7%** |
| 월간 그리드 빈 칸 | **약 78%** |
| 2일 과정 비중 | 15/20 = **75%** — 연속 2칸 span 필요 |

**캘린더는 밀도가 높을수록 이기는 포맷**인데 이 데이터는 월 6~8건이다. 78%가 빈 칸인 그리드는 정보를 주는 대신 **화면만 크게 차지한다.**

### 8-2. 반응형이 결정적이다

375px에서 7열 → 열당 **약 47px**. 날짜와 점 하나가 한계이고 과정명은 못 들어간다. 결국 **"점을 탭해 상세를 여는" 2단계**가 되는데, 지금 리스트는 **탭 없이 다 보인다.** 모바일에서 명백한 퇴보다.

### 8-3. 진짜 니즈와 대안

사용자가 캘린더를 찾는 순간의 질문은 **"이 날짜가 내 일정과 겹치나?"**이고, 그 답은 **사이트 캘린더가 아니라 사용자 본인 캘린더**에 있다.

**대안 A — 「캘린더에 추가」 ICS (권장 · P2)**

| 항목 | 내용 |
| --- | --- |
| 동작 | 회차 카드에서 `.ics` 1건 다운로드 → Outlook·Google·Apple에 등록 |
| 내용 | 과정명 · 일자(종일) · 장소 · `?course=&session=` 링크 |
| 왜 이기는가 | "겹치나?"에 **사용자의 실제 일정으로** 답한다 |
| 구현 | 문자열 생성 + Blob 다운로드. 서버 불필요 |
| 부수 효과 | 신청 전 단계에서 **일정을 선점**하게 만든다 |

**대안 B — 월 타임라인 스트립 (보류)** — 2일 과정이 막대로 자연 표현되나, 모바일에서 세로 타임라인이 되어 **리스트와 형태가 수렴**한다. 신규 정보를 주지 않는다. `UpcomingSessionsStrip`이 이미 유사 역할을 한다.

**결론**: **월간 그리드 캘린더는 만들지 않는다.**

| 회차 표기 | `12.9(수) ~ 10(목) (모집중)` | **`12.9(수) ~ 10(목) · 2일 (모집중)`** — 일수 추가 |
| 문의 유형 문구 | `공개교육 미개설 과정 상담 희망` | **`공개교육 상담 희망`** — 내부 용어('미개설') 제거 |
| ① 포맷 | `[관심 과정: X] ` (1줄, 끝 공백) | **2줄** — `· 문의 내용: ` 줄 추가로 ②③과 구조 통일 |
| 토큰 제거 | 각자 자기 것만 | **공용 strip 목록**으로 3종 전부 제거(§9-4) |

> **일수(`· 2일`)를 넣는 이유**: 수신 담당자가 날짜만 보고 1일/2일을 역산해야 했다. 회신 전에 알아야 할 정보이고, 화면 카드에도 이미 `2일 과정`으로 노출돼 있어 **화면과 폼이 같은 말을 한다.**

### 9-4. 토큰 누적 방지 — 단일 strip 목록

```ts
// lib/kium/openBridge.ts — 두 브리지가 공유하는 단일 출처
export const PREFILL_STRIP: RegExp[] = [
  /^\[공개교육 상담 신청\][\s\S]*?(?=\n\S|\n*$)/,   // ② ③
  /^\[관심 과정: [^\]]*\][^\n]*\n?(?:· 문의 내용:[^\n]*\n?)?/, // ①
];
```

- `dispatchPrefill`이 프리필 직전에 **3종 전부**를 제거한 뒤 새 토큰을 넣는다
- `inquiryBridge.ts`의 기존 정규식도 이 목록을 참조하도록 **일원화**한다
- 사용자가 직접 입력한 본문은 보존한다 — 제거 대상은 **헤드 블록만**

### 9-5. 유지되는 원칙 (변경 없음)
