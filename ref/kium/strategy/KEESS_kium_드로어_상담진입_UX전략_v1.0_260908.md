## 2. 원인 (추정 아님, 코드 확인)

### 실패 연쇄

```
① 시트 열림
   useModal(sheet && !!openCourse) → body.style.position = 'fixed'
                                     body.style.top = '-{y}px'
                                     body.style.overflow = 'hidden'
   (MO-03 스크롤 잠금 · lib/useModal.ts:35~42)

② 시트 안 「상담하기」 탭
   consultSession() → dispatchPrefill() · syncConsultQuery() · scrollToInquiry()
   (openBridge.ts:196~209)

③ scrollToInquiry() 의 scrollIntoView 실행
   ★ body 가 position:fixed 이면 문서 스크롤 높이가 뷰포트로 붕괴한다.
     스크롤할 공간이 없으므로 아무 일도 일어나지 않는다.

④ MI-04 의 visualViewport 보정(window.scrollBy)
   ★ 같은 이유로 무효.

⑤ 480ms 뒤 f-company.focus({preventScroll:true})
   ★ 시트 뒤에 있는 입력에 포커스가 걸린다. 키보드가 올라온다.

⑥ 시트를 닫는 코드가 없다
   ★ consultSession · consultCourse · consultMonth · consultOpenRequest 4개 진입점 중
     어디에도 시트를 닫는 호출이 없다. 브리지(openBridge)는 시트 상태를 모른다.
     시트 상태는 KiumCourseGrid 의 openId 에만 있다.
```

**사용자가 보는 것: 키보드만 올라온다.** 영상과 정확히 일치합니다.

### 근본 원인은 하나

**시트를 닫지 않는 것**입니다.

MO-03의 `position:fixed` 잠금은 이 결함을 **확정적 증상으로 드러냈을 뿐** 원인이 아닙니다. 잠금이 없었더라도 시트가 덮은 채로 배경이 스크롤되어 더 혼란스러웠을 것입니다.

### 함께 드러난 접근성 결함

`useModal`의 포커스 트랩은 **Tab 키만** 가둡니다. 프로그램적 `.focus()`는 막지 못합니다.

`aria-modal="true"` 다이얼로그가 열린 상태에서 **포커스가 배경 요소로 나갔습니다.** 스크린리더 사용자는 자신이 어디에 있는지 알 수 없게 됩니다. 시각 사용자에게는 "키보드만 뜨는" 현상으로, 보조기술 사용자에게는 더 심각한 형태로 나타나는 같은 결함입니다.

## 3. 왜 "시트 닫기"만 추가하면 안 되는가

`useModal` cleanup은 잠금을 풀면서 **스크롤 위치를 되돌립니다**(`lib/useModal.ts:84~91`).

```
Object.assign(body.style, prev)
html.style.scrollBehavior = 'auto'
window.scrollTo(0, y)          ← 시트 열기 직전 위치로 복원
```

닫기만 추가하면 순서가 이렇게 됩니다.

```
closeSheet()  →  scrollToInquiry()  →  (React 커밋)  →  scrollTo(0, y) 복원
                 폼으로 스크롤             스크롤이 원위치로 되돌아감
```

**폼으로 간 스크롤이 취소됩니다.** 증상만 "키보드만 뜸"에서 "잠깐 움직였다가 되돌아옴"으로 바뀝니다.

따라서 **닫기와 순서 보장이 함께** 필요합니다.

## 4. 전략 원칙

### 원칙 1. 상담 CTA는 상세 보기의 종료 지점이다

드로어는 "이 과정이 무엇인가"를 답하는 곳입니다. 「상담하기」는 그 질문이 끝났다는 신호입니다. 시트를 남겨 둘 이유가 없습니다.

### 원칙 2. 잠금이 풀린 뒤에만 스크롤하고 포커스한다

스크롤 잠금 상태에서의 스크롤 시도와 배경 포커스는 **둘 다 하면 안 되는 동작**입니다. 시점을 추측하지 말고 **잠금 해제를 관측**한 뒤 실행합니다.

### 원칙 3. 시트 상태를 아는 곳에서 닫는다

`openBridge`는 순수 브리지입니다. 시트 상태(`openId`)를 아는 곳은 `KiumCourseGrid`뿐입니다. 브리지에 시트 지식을 주입하지 않고, **시트를 소유한 컴포넌트가 자기 CTA를 감쌉니다.**

### 원칙 4. 인라인 패널 경로는 건드리지 않는다

같은 `KiumCoursePanel`이 데스크톱에서는 인라인 패널로, 모바일에서는 시트 안으로 렌더됩니다. 닫기는 **시트 경로에만** 필요합니다. 옵션 prop 패턴(기존 `showCourse`·`onCourseClick` 관습)으로 분기합니다.

### 원칙 5. 잠긴 상태에서는 차라리 아무것도 하지 않는다

잠금이 풀리지 않는 예외 상황에서 강행하면 **이번 버그를 그대로 재현**합니다. 타임아웃 시 중단이 옳습니다.

## 6. 채택하지 않은 대안

| 대안 | 판정 |
| --- | --- |
| `openBridge`가 시트 닫기 이벤트를 발행 | **기각.** 브리지에 시트 지식이 생깁니다. 구독자 관리·다중 인스턴스 문제가 따라오고, 시트를 소유한 컴포넌트에서 한 줄로 되는 일입니다 |
| 시트를 닫지 않고 상담 폼을 시트 안으로 | **기각.** 공유 폼 구조를 깨고 회귀 범위가 5개 페이지로 번집니다 |
| 고정 지연(`setTimeout 300`)으로 잠금 해제를 기다림 | **기각.** 기기·React 스케줄링에 따라 달라지는 값을 추측하는 것입니다. 잠금 상태는 `body.style.position`으로 **직접 관측**할 수 있습니다 |
| MO-03 잠금을 되돌림 | **기각.** 배경 스크롤 연쇄가 되살아납니다. 잠금은 옳고 순서가 틀렸습니다 |
| `useModal`에 잠금 해제 이벤트 추가 | **기각.** 5개 페이지가 공유하는 훅입니다. 호출부에서 관측으로 해결 가능합니다 |
