Next.js(App Router) + React + TypeScript + Tailwind v3.4 기반 **B안 5페이지 정적 사이트**.
디자인 기준: [`ref/design/Design.md`](ref/design/Design.md) · 확정 프로토타입([`ref/prototype`](ref/prototype)).

## 데이터 소스 — 사회공헌

- **본문·메타**: `lib/csr/data.ts` 36건. kggroup.co.kr 공식 사회공헌 페이지에서 **1회성으로 수집한 정적 스냅샷**이며, 각 건의 `sourceUrl`이 원문을 가리킵니다. API·CMS 연동 없음.
- **이미지**: `public/img/csr-{번호3자리}-{순번2자리}.{jpg,png}` 76개(카드용은 `-thumb` 접미사). 외부 핫링크 없이 전건 self-host. 1MB 초과 원본 7개는 `scripts/resize-csr-images.mjs`로 최대 폭 1600px·품질 80 재저장(파일명 불변).
- **미노출 항목**: 날짜·조회수·검색은 화면에 내지 않습니다. `sortDate`는 정렬 전용이고, 조회수는 `/csr/[id]` 라우트의 GA4 페이지뷰로 갈음합니다(코드에 집계 로직 없음).
- **갱신**: 콘텐츠 추가·수정은 `lib/csr/data.ts` 편집 + 이미지 배치 후 재빌드로 반영됩니다. 원문 링크는 외부 사이트 개편에 따라 끊길 수 있어 주기적 생존 점검이 필요합니다.

## 데이터 소스 — 인재키움 프리미엄

- **과정 19건**: `lib/kium/data.ts` — HRDK 신청원본 xlsx(시트2·3) + 과정개요서에서 **사전 추출·대조 완료된 산출물**. 수치는 소스 문서 개정을 통해서만 바꿉니다.
- **`ref/kium/build/`는 추출 원본(감사 추적)** 으로 보존하며 `lib/`과 동기화하지 않습니다. 최초 이식 시점에는 바이트 동일이었고, 이후 **사업 확정 개정분만 `lib/`에 반영**돼 아래만큼 갈라져 있습니다 — 소개문 7건(§19) · kium-02 `target` 표기 `경력신입사원` → `경력 신입사원`(§21) · **교육구성 `modules` 19건 전건(§22)** · **`category` 19건 전건 재지정 + `subCategory` 필드 삭제 + `target` 5건(§45)**. 확정본이 추출 원본을 소급 수정하면 대조 근거가 사라지므로 의도된 분기이며, `ref/`가 곧 교체 전 원본의 보존처입니다.
- **카테고리 7종**(`lib/kium/data.ts` `KIUM_CATEGORY_META`): 신입·온보딩 3 · 승진자 3 · 리더십·관리자 3 · AI활용 3 · 비즈니스 역량 3 · 커뮤니케이션·조직활성화 3 · CS·민원응대 1 = **19**. 필터 칩 라벨·카운트는 이 상수와 `KIUM_COURSES` 실측에서 파생되므로 하드코딩된 목록이 없습니다(§45).
- **콘텐츠 상수**: `lib/kium/content.ts` — 히어로 카피·지원개요·자격확인 3경로·신청절차 4스텝·유의사항·**FAQ 9문항**(초안 7 `draft` + 공개교육 2 `confirmed`, `tag`로 구분)·공식 링크·검증 수치(`facts`)·공개교육 탭 카피(`open`).
- **공개교육 회차 20건**: `lib/kium/sessions.ts` — 요청 원문 「※공개교육 일자※」 표(260903) 1:1. **요일 문자열은 저장하지 않고 `start`에서 파생**합니다(요일 오기 구조적 차단). 이 설계가 실제로 값을 했습니다 — `relead-r3`의 원문 `12/17(수)~18(금)`에서 틀린 것은 **요일 라벨 하나뿐**(2026-12-17=목)이고 날짜 17~18은 2일 과정과 정합하므로, 원문 날짜를 그대로 넣으면 화면에 `12.17(목) ~ 18(금)`으로 **자동 교정**되어 나옵니다(§50에서 복원) → 노출 회차 수 **20**(`KIUM_SESSION_TOTAL` 파생, 수기 숫자 없음) · 월별 10월 6 / 11월 6 / 12월 8. **개설 과정 판별의 단일 기준**도 이 배열입니다 — `isOpenCourse()`가 `courseId` 존재 여부만 보고, 별도 플래그가 없습니다(§49). ⚠️ `status`는 사업부 회신 전이라 **전건 `'recruiting'`으로 초기화**돼 있습니다(§50 — 이전 시드가 미래 회차를 '마감'으로 노출시켰습니다). 배지 4종 시각 검증은 `?preview=badges` 쇼케이스가 전담합니다.
- **공개교육 교육비 9건**: `lib/kium/pricing.ts` — 원천 xlsx 시트「2. 신청 훈련과정 정보」 **N열(훈련비 단가 · 1인 기준)**. **O열(총 훈련비)은 화면에 쓰지 않습니다** — `N열 × M열(훈련인원)`로 계산된 과정 총액이라 1명 단위 신청 화면에 쓰면 금액을 오해시킵니다. `KIUM_PRICE_VERIFIED` 게이트가 `false`면 금액 대신 `비용은 상담 시 안내`를 노출합니다.
- **수치 검증 게이트**: `lib/kium/facts.ts`. `verified:false` 항목은 **화면 렌더 차단**이며 접근 시 대체 문구(`기업별 상이 — 상담 시 확인`)와 개발 모드 경고를 반환합니다. 컴포넌트는 이 게이트만 경유합니다(직접 접근 0건).
- **미노출 항목**: 강사·NCS 분류·환급 소요기간·지역별 차등 환급율은 데이터에도 화면에도 없습니다. **교육 단가는 공개교육 9과정만 예외로 노출**(1인 기준 N열)하며, 위탁 10과정은 `교육 일정`·`교육비` pill 자체를 렌더하지 않습니다(`"-"` 표기 금지 · §48).
- **외부 링크**: 정부·공단 도메인 3종만(`work24.go.kr` · `total.comwel.or.kr` · `hrdkorea.or.kr`). 경쟁 훈련기관 URL 금지.

## 개발 · 빌드

```bash
npm install
npm run dev       # http://localhost:3001  (B안 로컬 컨벤션: 3000=A안, 3001=B안)
npm run build     # 정적 빌드 (SSG)
npm run start     # 빌드 결과 서빙 (http://localhost:3001)
npm run test:hero # 모바일 헤더/히어로 겹침 회귀 테스트 (Playwright · 2페이지 × 4뷰포트)
```

> **`.next`는 프로젝트당 하나**입니다. `next dev`를 두 개 띄우거나 dev 서버가 뜬 채로 `next build`를 돌리면
> 산출물이 섞여 서버가 500(`Cannot find module './###.js'`)을 뱉습니다. 이 경우 모든 서버를 내리고
> `.next`를 삭제한 뒤 다시 빌드하세요. `npm run test:hero`가 dev 포트(3001)를 그대로 재사용하는 것도 같은 이유입니다.

## 배포 (Vercel 권장)

**현행 배포**: `keess-pedu` → **https://keess-pedu.vercel.app** (프로젝트 `dilong006-2035s-projects/keess-pedu` · `main` 자동 배포)
`*-dilong006-2035s-projects.vercel.app` 계열 프리뷰 도메인은 **배포 보호(SSO)가 걸려 있어** 익명 접근 시 본문이 내려오지 않습니다. 외부 공유·자동 검증은 위 프로덕션 도메인을 쓰세요.

1. 저장소를 Vercel에 연결 → 프레임워크 자동 감지(Next.js).
2. 빌드 커맨드 `next build`, 출력 자동. 환경변수 없음.
3. 전 페이지 정적(SSG)이므로 정적 호스팅(Netlify/S3+CloudFront 등)도 가능.

## 백엔드 없음 (연동 슬롯)

- 문의/상담/가이드/다운로드 게이트·부정훈련 신고는 **클라이언트 검증 + 성공/데모 상태 UI**입니다.
- 실전송은 각 폼의 `onSuccess`/submit 지점에 향후 엔드포인트(사내 API·메일 서비스)를 연결하면 됩니다.

> 기준: `ref/spec/KEESS_P1P2_모바일히어로상단_개선_기술명세서_및_프롬프트_v1.0_260810.md`. 표현 계층 한정 — 카피·정보구조·데이터·데스크톱 레이아웃 무변경.

### 23) 카운트업 수치가 정적 HTML에 `0`으로 박히던 문제
> `components/common/CountNum.tsx` 1개 파일. 사용처는 `/ax-ai` 히어로 플로트 3종·벤토 스탯 2종뿐이며 카피·레이아웃·모션 타이밍 무변경.

- **문제**: `useState(0)`으로 시작해 뷰포트 진입 시 목표값까지 세는 구조라, **서버가 만든 정적 HTML에는 항상 `0`이 들어간다**. JS 실패·크롤러·JS 비활성 환경에서 `0 AX Framework 단계`처럼 사실과 다른 수치가 그대로 노출됐다.
- **처방**: 초기값을 **최종값**으로 두고, 카운트업을 실제로 돌릴 수 있다고 확인된 뒤에만(클라이언트 + 모션 허용 + `IntersectionObserver` 지원) `useLayoutEffect`로 **페인트 전에 0으로 되감는다**. 되감기가 화면에 보이지 않아 애니메이션 체감은 종전과 같고, 조건이 하나라도 어긋나면 되감기 자체가 일어나지 않아 최종값이 그대로 남는다.
- **`useEffect` 대신 `useLayoutEffect`인 이유**: `useEffect`는 페인트 후에 돌아 최종값 → 0 → 카운트업의 **숫자 깜빡임**이 눈에 보인다. 서버에서는 `useLayoutEffect`가 경고를 내므로 `typeof window`로 분기해(`useIsoLayout`) SSR에서는 `useEffect`로 대체한다.
- **`prefers-reduced-motion`·IO 미지원**: 되감기를 건너뛰므로 최종값이 처음부터 표시된다(종전 동작과 동일한 결과, 경로만 단순해졌다).
- **검증**: `npm run build` 경고·에러 0 · 빌드 산출 `/ax-ai` HTML의 `.num` 5개가 실제 수치(5/8/5/8/5)로 렌더되고 `class="num">0<` **0건**.

- **세그먼트 카운트 단위 불일치** — 좌측은 과정 수(19), 우측은 회차 수(19)였다. 공교롭게 둘 다 19라 "공개교육도 19개 과정"으로 읽혔고 바로 아래 `분야 전체 9`와 모순이었다. 세그먼트는 **보기 범위**를 고르는 컨트롤이므로 양쪽 모두 과정 수로 통일했다(`공개교육 9`). 회차 수는 섹션 헤더가 말한다.
- **「기간」 칩의 맨숫자는 일수로 읽힌다** — `10월 6`은 "6일짜리" 또는 "10월 6일"로 오독된다. 이 축에만 `N회차` 단위를 붙였다(`전체 20회차 / 10월 6회차 / 11월 6회차 / 12월 8회차`) + `aria-label` 전건. 분야·모집 상태는 무변경 — 세 축 모두에 단위를 붙이면 모바일에서 필터 바가 3줄이 되고, 그 두 축은 맨숫자가 '개수'로 자연스럽게 읽힌다. 숫자는 `.cnt`(tabular-nums), 단위는 `<i>`로 분리해 한글에 등폭이 걸리지 않게 했다.
- **섹션 헤더가 필터를 반영하지 않았다** — `10~12월`이 하드코딩이라 12월만 걸러 본 사용자에게 표시와 상태가 어긋난 화면이 남았다. 필터에서 `scopeLabel`을 파생시켰다(`12월` / `12월 · 모집중`).
- **`정부지원 환급` 칩 제거** — 19/19 전 카드에 붙어 변별력이 0이었고, 지면에서 가장 진한 색(`--gov`)이라 카드마다 다른 대상·시간보다 먼저 읽혔다. 스크린리더는 카탈로그를 훑을 때 19번 반복 낭독했다. **대체 문구는 두지 않는다**(v1.1 §3-4) — 히어로가 탭 위에서 이미 `훈련비의 90~95%는 환급 받고`를 말하고 사업소개 탭 전체가 환급 설명이다. 카탈로그는 과정을 **고르는** 자리라 19개 전건에 공통인 사실은 고르는 데 기여하지 않는다. 공개교육 보기의 보조 문구도 v2.0에서 `1명부터 신청 가능`만 남겼다(BT-16) — 환급은 히어로·사업소개 탭 소관이다. `공개교육` 칩은 9/19에만 붙어 변별력이 있으므로 존치. `.kium-badge.gov` CSS 규칙은 전역 검색 결과 다른 사용처가 없었으나 토큰 삭제는 별건이라 남겼다.
- **상세 패널 `교육 일정` → `공개교육`** — 라벨이 '이 과정 전체의 일정'으로 읽히는데 실제로는 공개교육 회차만 나열한 것이고, 이 과정들은 기업 위탁으로도 운영된다(`schedule: '연중상시'`). **라벨이 사실과 다르게 읽히는 문제**였다. 공개교육 전용 pill 2종(`공개교육`·`교육비`)에 `data-open`을 주어 위탁 공통 정보(대상·형태·시간·정원)와 시각적으로 갈랐다(`--p3` 파생 `color-mix`, 신규 토큰 0).
- **인트로 카피** — `일부 과정은…`은 첫 단어가 제약이라 "내 관심 과정은 아니겠지"로 넘긴다. **사업 확정본** `혼자서도 부담 없이 신청할 수 있는 공개교육 과정을 확인해보세요.`로 교체했다(임의 수정·윤문 금지 대상). ⚠️ 같은 페이지 FAQ 2번이 "개인 자격의 신청·결제는 지원되지 않습니다"라 `혼자서도`를 개인 결제로 읽을 소지가 남는다 — 명세 v1.1 §3-5·부록 B **D10**이 이를 인지하고 있으며, FAQ 공개교육 Q1 답변 첫 문장에 신청 주체가 기업임을 병기하면 한 줄로 해소된다(문서 확정 전이라 미적용).
- **`aria-live` 문구 시각 노출** — `.kium-sr`로 숨겨져 스크린리더 사용자만 듣고 눈으로 보는 사용자는 무엇이 바뀌었는지 알 수 없었다. `.kium-livenote`로 필터 바 아래에 내놓고 빈 문자열이면 렌더하지 않는다.
- **표기 통일**: `공개교육` 붙여쓰기 — 요청 원문·FAQ 확정 문안·기존 코드가 전부 붙여쓰기다.
- **썸네일(BT-10)은 미착수** — 신규 10장(kium-01·02·05·06·07·08·15·16·17·18)이 아직 없다. 인물 얼굴 식별 컷 정책이 선결 조건이라 이미지가 준비될 때까지 `openThumbs.ts`·`thumbs` prop·`alt` prop 현행 유지.
#### v2.0 개정분 — 같은 정보를 두 곳에서 말하지 않는다

- **★「전체 일정」이 '추가 전개'가 아니라 '교체'다(BT-18)** — 이전 구조는 스트립을 그대로 둔 채 아래에 전체 리스트를 덧붙여 `10.12 Agent` 같은 회차가 **한 화면에 두 번** 나왔다. 두 영역의 관계가 '요약 → 전체'인데 요약이 사라지지 않으니 경계가 성립하지 않았고, 그것이 "어디서 어디까지 바뀌는지 모르겠다"의 실제 원인이었다. 같은 자리에서 **요약 6장 ↔ 전체 목록**을 갈아 끼운다(중복 0). 모드 헤더를 `header` prop으로 받아 `.kium-schedbox` 한 덩어리로 묶고 토글을 헤더 행 우측(모바일은 헤더 아래 전폭)으로 올렸다. 토글 라벨은 **다음 상태가 아니라 결과**를 말한다 — 접힘 `전체 일정 20개 회차` / 펼침 `간략히 보기`. `.kium-ustrip-wrap`·`.kium-ustrip-foot`는 폐지.
- **`live`의 용도를 바로잡았다(BT-13)** — v1.1은 이 값을 '필터 결과'로 보고 시각 노출을 지시했으나 **실제 내용은 '보기 전환 안내'**였다. 전환 사실은 세그먼트 `aria-pressed` 변화·필터 행 등장·헤더 문구 변화가 이미 3중으로 알리므로 눈에 보이게 해봐야 중복만 는다. 문구 자체를 없애고 `aria-live` 통로에는 **필터 결과 건수**(`12월 · 모집중 8개 회차`)를 싣는다 — 스크린리더는 헤더의 시각 변화를 스스로 감지하지 못해 이 통로가 유일한 고지 수단이다. `.kium-livenote`는 폐지하고 `.kium-sr`로 돌아갔으며, **조건부 렌더도 걷어냈다** — aria-live 영역은 내용이 바뀌기 전부터 DOM에 있어야 읽힌다.
- **회차 CTA 라벨 `이 일정으로 상담` → `상담하기`(BT-17)** — 한 화면에 20회 이상 반복되는 문장이라 `이 일정으로`는 정보가 아니라 배경이 됐고, 7자 버튼이 모바일 1열에서 날짜·과정명 폭을 빼앗았다. **카드 안에 있으면 그 일정인 것이 자명하다.** 저빈도 2상태(`마감 전 상담`·`다음 회차 상담`)는 문구 자체가 상태 정보를 지므로 유지했다. `SessionCard`의 회차 pill 접근명도 같은 값으로 맞췄다.
- **인트로 링크 `공개교육 일정 보기` → `일정 보기`(BT-15)** — 앞 문장이 이미 '공개교육'과 '확인해보세요'를 말한다. 시각은 짧게, 낭독은 온전하게 — `aria-label="공개교육 일정 보기"`로 접근명만 전체 맥락을 진다. 간격은 공백 문자가 아니라 `margin-left`가 준다(공백은 줄바꿈 위치에 따라 사라진다). <640px에서는 블록으로 내려 44px 타깃을 확보한다.
- **세그먼트 라벨 붙여쓰기(BT-14)** — `전체 과정` → `전체과정`. `공개교육`과 4자 대칭이 되어 좁은 폭에서 두 칩 폭이 균등해진다. 전역 표기 원칙(`공개교육` 붙여쓰기)과도 일치한다.
- **모드 헤더 보조 문구에서 환급 제거(BT-16)** — `1명부터 신청 가능 · 정부지원 환급` → `1명부터 신청 가능`. §3-4와 같은 근거다.

#### v2.1 개정분 — 회차 카드에서 같은 회차를 두 번 가리키지 않는다

- **상태 배지 + CTA를 버튼 하나로 통합(BT-20)** — 배지와 버튼이 세로로 붙어 **같은 회차를 두 번** 가리켰다. 카드 요소가 5개(날짜·일수·과정명·배지·버튼)라 세로가 길고, 모바일 가로 스크롤 카드에서 특히 불리했다. **배지 자체를 버튼으로 만들지는 않았다** — `모집중`은 상태(명사)라 버튼 라벨이 동작을 말하지 않고, 배지는 관례상 '정보'여서 클릭 가능하다고 학습돼 있지 않으며, 마감과 신청 가능 상태가 같은 형태가 되어 무엇이 눌리는지 색에만 의존하게 된다. 대신 **배지를 버튼 안으로 흡수**했다(좌: 상태 배지 / 우: `상담하기 →`). 요소 5개 → **4개**, 390px 카드 높이 **196px → 164px(−16%)**.
  **마감은 형태 자체를 바꾼다** — `aria-disabled` 버튼은 스크린리더에 혼선을 주므로 정적 배지 + `다음 회차 상담` 텍스트 링크로 요소를 교체했다(`SessionCta`의 closed 철학 승계). "마감은 이벤트를 걸지 않는다"가 색이 아니라 **형태**로 표현된다.
  적용 범위는 `.kium-scard2`(스트립 카드 · 상세 패널 회차 카드)뿐이다. `SessionListView`의 `.kium-srow`는 **가로 배치**라 배지와 CTA가 이미 좌우로 갈려 있고 세로 절약 효과가 없어 현행을 유지했다. 기존 `SessionBadge`·`SessionCta`는 `BadgeShowcase`·`SessionListView`·`KiumOpenHero`가 계속 쓰므로 **삭제하지 않았다**.
- **회차 카드 과정명 밑줄 제거 + hover·focus 복원(BT-19)** — 스트립 6장과 상세 패널에 반복돼 시각 노이즈가 됐다. 다만 `--p1`(#2E1A6B)과 이웃 `--muted`(#54585f)의 대비가 **약 1.7:1**로 WCAG G183이 권하는 3:1에 미달해 **색만으로는 어포던스가 부족하다** → 기본 상태에서 밑줄을 빼되 **hover·focus-visible에서 복원**했다(종전에는 색만 바뀌었다 — 이 부분도 함께 고쳤다). 「전체 일정」 리스트의 `.kium-srow-title`이 정적 텍스트라 두 뷰의 시각도 이로써 통일된다. 44px 히트 영역(`padding`/음수 `margin`)과 `.is-static` 규칙은 무변경.

- **검증**: `verify-btype.mjs` **53/53 PASS** + 신규 `verify-btype2.mjs` **32/32 PASS**(카운트·라벨 12 · 프리필 P1~P9 · 공유 폼 회귀 R1~R5 · 5뷰포트 · 금지어 렌더). 헤드 중복 회귀(P6·P7)를 스위트에 상시 감시로 넣었다. 320~1440 가로 넘침 0px · 기간 칩 전 구간 1줄 · 44px 미만 타깃 0. `tsc --noEmit` 0 · `next build` 경고 0 · 신규 의존성 0.

### 49) /kium B type 재편 — 공개교육 탭 숨김 + 과정안내 「보기 전환」 (Btype 명세 v2.0 · 전략 v1.1)
> 기준: `KEESS_kium_Btype_기술명세서_v2.0_260904.md`(전략 v1.1 통합본) — **저장소 외부 문서**로 전달돼 `ref/kium/spec/`에 사본이 없다. 백업 태그 `backup/btype-20260904-1011`.
> A/B 비교를 위한 변인 통제가 목적이라 **회차 UI(SessionBadge·SessionCard·상세 패널·프리필)는 A type 그대로 재사용**하고, 배치만 바꿨다.

- **구 진입 경로 보호** — `?tab=open` · `#open`으로 들어오면 `?tab=courses&mode=open`으로 조용히 바꾸고(`replaceState`) 공개교육 보기로 연다. 리다이렉트 효과는 부모(KiumTabs)에 있고 자식 효과가 먼저 실행되므로, `KiumCoursesTab`도 원본 형태를 독립적으로 인정한다 — 실행 순서에 기대지 않는다.
- **컨트롤은 필터 칩이 아니라 세그먼트 토글** — `[ 전체 과정 19 | 공개교육 일정 n ]`. 이 컨트롤은 목록을 줄이는 게 아니라 스트립·모드 헤더·회차 레이어를 통째로 켜고 끄므로, 겉모습이 그 무게와 일치해야 한다(전략 v1.1 R1). 페이지 탭과 혼동되지 않게 `role="tablist"`를 쓰지 않고 `aria-pressed` 토글 2개 + 전환 시 `aria-live` 안내로 만들었다.
- **개설 판별은 단일 기준** — `KIUM_SESSIONS`에 `courseId`가 있는가 하나뿐이다(`isOpenCourse`). 데이터 플래그를 새로 만들지 않았다.
- **전체 보기에서 회차 요소는 DOM 자체가 없다** — 스트립·모드 헤더·회차 레이어·기간/모집 상태 필터 전건 미생성(정적 HTML 실측 0건). 예외는 개설 과정 카드의 아웃라인 뱃지 9건뿐이다.
- **뱃지는 카드 안이 아니라 형제로 놓았다** — `.kium-card`가 `<button>`이라 뱃지를 안에 넣으면 중첩 인터랙티브가 된다. `.kium-card-wrap`에 절대 배치해 확장 토글과 이벤트를 **물리적으로** 분리했다(버블링 차단에 기대지 않는다). 클릭 시 그 카드의 화면 높이를 기억했다가 전환 후 되돌려, 보던 자리를 잃지 않는다.
- **모드 헤더 1줄** — `공개교육 일정 · 10~12월 {n}개 회차` / `1명부터 신청 가능 · 정부지원 환급`. 숨긴 탭의 인트로 문단과 3-스탯 카드 행을 이 한 줄이 대신한다(스탯 카드 행 미생성). 회차 수만 필터와 연동되고, 분야 칩의 `[전체]`는 **보기별 카탈로그 규모(19/9)로 고정**한다 — 필터마다 같이 줄면 분류별 고정 카운트와 축이 어긋난다.
- **`UpcomingSessionsStrip` 신설** — PC/TB 6장 · MO 3장, `closed` 제외 · 날짜 오름차순 · 필터 연동. 카드는 A type `SessionCard`를 스타일 재정의 없이 쓰고 `showCourse` prop만 켠다(미지정 시 상세 패널 렌더 무변경). 과정명 클릭 → 그리드 카드로 스크롤 + 확장 + 2초 하이라이트 + 포커스(`preventScroll` 필수 — 없으면 포커스가 스크롤을 다시 잡는다), CTA → 프리필 직행.
- **「전체 일정」은 인라인 전개** — PC/TB 텍스트 버튼(재클릭 접힘) / MO 풀폭 `전체 일정 보기 (n개 회차)`. 별도 페이지·탭을 만들지 않아 탭 2개 수치를 지킨다. 목록은 A type `SessionListView` 행 규격 그대로이며, 경로 C 미탑재라 월 그룹 CTA만 `showMonthCta={false}`로 렌더하지 않는다(코드는 보존).
- **리드 회수 2종** — 그리드 하단 `과정 개설 상담`(`· 문의 유형: 공개교육 미개설 과정 상담 희망`) · 시즌 오프 `개설 알림 상담`(`· 문의 유형: 공개교육 개설 일정 안내 요청`). 둘 다 프리필 경로 B 변형이고 문구는 `OPEN_REQUEST_TYPE` 한 곳에만 있어 본문과 요약 배너가 어긋날 수 없다.
- **시즌 오프(미래 회차 0건)에도 아무것도 숨기지 않는다** — 세그먼트는 `공개교육 일정 0`으로 정직하게 표기하고 뱃지 9건도 그대로 둔다. 다음 시즌에 같은 자리에서 발견돼야 하기 때문이다. 시드 일자를 과거로 밀어 시뮬레이션 후 **원복 확인**했다.
- **계측** — 저장소에 dataLayer(GTM)가 없어 `data-evt` 표식만 부착했다(`kium_mode_open` · `kium_session_cta`+courseId/sessionId/status · `kium_consult_reach`+path). `kium_consult_submit`은 5개 페이지가 공유하는 `HomeInquiry` 제출 버튼에 걸려야 하는데 공유 폼 수정은 타 페이지 회귀 위험이 있어, `/kium` 제출 스코프에만 표식을 남기고 실제 바인딩은 dataLayer 도입 시점으로 미뤘다.
- **검증**: 브라우저 회귀 **53/53 PASS**(`scripts/verify-btype.mjs`) — 탭 숨김·구 쿼리 리다이렉트 2종·딥링크·보기 전환 11종·스트립 9종·MO/TB·필터 상태 4종 단독 및 0건·프리필 A/B/마감가드/무효 id·쇼케이스·타 페이지 5경로. 추가로 시즌 오프 시뮬레이션(PC/MO), `SHOW_OPEN_TAB=true` 복원, reduced-motion(애니메이션·scroll-snap 무효화), 44px 타깃, 뒤로가기 스택 미오염을 실측했다. `tsc --noEmit` 0 · `next build` 경고 0 · 신규 npm 의존성 0.
- **배포본 재검증**: https://keess-pedu.vercel.app 기준 **53/53 PASS** + 3경로 콘솔 에러·경고 0 + 5뷰포트 가로 넘침 0px. 로컬 산출물과 결과가 동일해 빌드-배포 간 편차가 없음을 확인했다.

### 48) /kium '공개교육' 탭 신설 — 회차 일정·교육비·회차→폼 프리필 (G2-01-04 v1.1)
> 기준: `ref/kium/spec/KEESS_G2-01-04_공개교육탭_기술명세서_v1.1_260903.md` (v1.0은 구버전). 신규 11파일 + 개정 11파일. `/kium` 3번째 탭 `#open` 신설, **신규 라우트 0건 · 신규 색/라운드/그림자 토큰 0건 · 폼 수집 필드·동의 구조 변경 0건.**

- **먼저 고친 것은 새 기능이 아니라 기존 결함이다** — `KiumTabs.indexFromHash()`가 미등록 해시에 `0`(사업소개)을 폴백해, `#inq` 앵커를 누르면 탭이 사업소개로 튀었다. 공개교육 CTA가 전부 `#inq`로 수렴하므로 방치하면 즉시 발현된다. `null` 반환 → 현재 탭 유지로 바꾸고 **회귀 R2·R3를 먼저 통과시킨 뒤** 나머지 작업을 시작했다. 최초 마운트에서 해시가 없으면 `active` 초기값 `0`이 그대로라 기존 기본 동작은 변하지 않는다.
- **회차 데이터에 요일 문자열을 저장하지 않는다** — `sessions.ts`는 `startDate`/`endDate`(ISO)만 갖고 `(월)`·`(화)` 표기는 전부 `fmtRange`/`fmtRangeA11y`/`fmtRangePrefill`에서 파생한다. 요일 오기를 구조적으로 불가능하게 만드는 설계이며, 실제로 원문 표에서 요일 오기 1건(`12/17(수)`=실제 목요일)이 발견됐다. 부록 A 20건의 **화면 표기가 명세 표와 문자 단위로 일치**함을 자동 대조로 확인했다.
- **일자 미확정 1건은 삭제도 추정도 하지 않았다** — `relead-r3`는 원문 `12/17(수)~18(금)`이 달력과 어긋나고(2026-12-17=목) 2일 과정인데 수~금 3일이다. (a)일자 유지·요일 정정 / (b)수~목 패턴 유지 중 무엇인지 사업부 회신 전까지 `tbd: true`로 두고 **매트릭스에만 `일정 조율 중` 비활성 렌더**한다. 리스트·집계에서는 제외되므로 히어로 지표는 `KIUM_SESSION_TOTAL` = **19**로 자동 계산된다(수기 숫자 0).
- **⚠️ 모집 상태 20건은 추정값이다** — `status` 필드는 요청 시안 캡처 기준이며 **원문 근거가 없다**(부록 C8). 파일 상단에 경고 주석을 남겼고, 오픈 전 실제 모집 상태로 전건 교체해야 한다. 전건 `'open'`도 유효한 확정안이다. 날짜 기반 자동 추론은 하지 않았다.
- **날짜가 지난 회차에 신청이 들어오는 사고를 코드로 막았다** — 운영 담당자가 배지를 못 바꿔도 마운트 후 `isPast()`인 회차는 `effectiveStatus()`가 `closed`로 **강제 승격**한다. 시계를 2026-11-20으로 고정한 실측에서 19건 중 12건이 `closed`로 승격되고 기본 숨김 + `지난 회차 12건 보기` 펼침이 동작했다.
- **마감을 만난 사용자를 그대로 보내지 않는다** — `closed` 회차 클릭은 프리필하지 않고 `이 회차는 마감되었습니다. 가장 빠른 다음 회차: {날짜} [신청하기]`를 `aria-live="polite"`로 띄운다. 마감 셀을 `disabled`로 만들지 않은 이유는 **`disabled`가 포커스를 못 받아 스크린리더가 셀의 존재 자체를 놓치기 때문**이다.
- **매트릭스는 `role="grid"`가 아니라 실제 `<table>`이다** — `<caption class="kium-sr">` + `th[scope="col"]` 4 + `th[scope="row"]` 9. **교육비는 행 헤더에만** 둔다(가격은 과정 단위 속성이라 셀에 넣으면 3회 반복되고 셀이 과밀해진다). 빈 셀에 `"-"`를 렌더하지 않고 `.is-empty` 톤다운 + `.kium-sr` 대체 텍스트만 둔다 — 실측 `"-"` **0건**.
- **1024px에서 매트릭스를 버린다** — 과정명 열 200px + 월 3열 × 160px = 680px가 표의 실질 최소 폭이고 그 아래에서는 폰트 축소(11px 이하)나 가로 스크롤 외에 선택지가 없다. 둘 다 접근성 기준 위반이라 **일정순 리스트로 전환**한다. 다만 뷰포트는 기본값만 정하고 **두 보기는 모든 뷰포트에서 전환 가능**하다.
- **리스트는 날짜가 최상단·최대 위계다** — 이 순서가 뒤집히면 매트릭스의 열화판이 된다. 정렬은 시작일 오름차순이며 월 단위로 그룹한다. **초기 구현에서 정렬을 빠뜨려 월 그룹이 18개로 쪼개졌고**, 빌드 산출 HTML 실측(`kium-list-mh` 18개)에서 잡아 수정했다. 수정 후 10월 6 / 11월 6 / 12월 7 = 19건, `11.30(월) ~ 12.1(화)`가 12월 그룹 선두에 정상 배치된다.
- **공유 폼(`HomeInquiry`)은 `+9/−4`, 프리필 핸들러 1곳만 건드렸다** — 이 폼이 사이트 전체 문의를 받으므로 유일한 고위험 지점이다. 프리필 상태 시각화는 폼을 고치는 대신 **폼 바깥에 `KiumApplySummary`(`role="status"`)를 두는 것**으로 해결했다. `data/home.ts`는 `INQ.trainees`에 `{ value:'lte9', label:'1~9명' }` **1개만** 추가했다 — 신규 수집 항목이 아니라 기존 셀렉트의 옵션 값이며 페이로드 스키마·동의 문구는 그대로다.
- **`1~9명` 옵션이 없으면 전환이 마지막 단계에서 끊긴다** — 히어로와 FAQ에서 "1명부터 신청 가능"이라고 말한 직후 폼의 최소 선택지가 `~ 50명`이면 사용자는 본인이 대상이 아니라고 판단하고 이탈한다. 회차 클릭 시 `예상 교육인원`이 **`1~9명` 선택 상태로 진입**한다(실측 `value=lte9`).
- **개인정보·마케팅 동의는 어떤 경우에도 자동 체크하지 않는다** — 프리필이 채우는 것은 `문의 내용`과 `예상 교육인원` 2개뿐이다. 실측 **자동 체크 0건**.
- **FAQ는 배열을 나누지 않았다** — 기존 7문항 배열에 2문항을 추가하고 `tag`로만 구분한다. 문안이 한 곳에만 존재해야 사업소개 탭과 공개교육 탭의 답이 어긋나지 않는다. 컴포넌트도 새로 만들지 않고 `KiumFaq`에 `items` prop을 주입했다(미지정 시 기존 동작 그대로).
- **삽입 위치가 설계 요소다** — 기존 2번 문항은 "개인 자격의 신청·결제는 지원되지 않습니다"이고 신규 문항은 "1명부터 신청 가능"이다. 실무적으로 모순이 아니지만(신청 주체는 어느 쪽도 기업) **떨어져 있으면 모순으로, 붙어 있으면 보완 설명으로 읽힌다.** 목록 끝이 아니라 2번 **직후**(Q3·Q4)에 넣었다. 공개교육 탭에서는 태그된 2문항만 Q1·Q2로 재번호돼 노출된다.
- **교육비는 원천 N열(1인 단가)만 쓴다** — O열(총 훈련비)은 `N열 × M열(훈련인원)`로 계산된 **과정 총액**이라 1명 단위 신청 화면에 쓰면 협상 스킬 과정 옆에 `12,000,000원`이 붙는다. 소스·빌드 산출물 전역에서 O열 계열 숫자 **0건** 확인. 단가 노출은 **공개교육 9과정 한정** 예외이고(선행 명세 최종 v2.0 §6-5 개정), 위탁 10과정은 `교육 일정`·`교육비` pill 자체를 렌더하지 않는다(`"-"` 표기 금지).
- **⚠️ 명세 §7-4의 딥링크 표기가 표준 URL에서 동작하지 않는다** — `/kium#open?view=date&month=11`은 브라우저가 `hash="#open?view=date&month=11"`, `search=""`로 파싱해 **탭도 안 열리고 쿼리도 안 읽힌다**. `KiumTabs`를 고치는 대신 `KiumOpenTab` 마운트 시 해시 속 쿼리를 `location.search`로 정규화(8줄)했다. 딥링크 4종 전부 정상 동작 확인.
- **⚠️ 딥링크 프리필이 유실되던 경합을 잡았다** — 자식(`KiumOpenTab`)의 마운트 효과가 형제(`HomeInquiry`·`KiumApplySummary`)의 구독 등록보다 **먼저** 실행되므로, 즉시 `dispatchEvent`하면 아무도 듣지 못한다. 1차 QA에서 실제 FAIL로 잡혔고 `setTimeout(…, 0)` 한 틱 지연으로 해소했다.
- **같은 그리드를 두 번 렌더하면 DOM id가 충돌한다** — 공개교육 탭이 `KiumCourseGrid`를 9과정으로 재사용하는데 패널 id가 `kium-panel-{id}`라 과정안내 탭과 겹쳤다. `getElementById`가 **숨겨진 다른 탭의 패널**을 잡아 스크롤 계산이 어긋난다. `idPrefix?: string`(기본 `''` = 기존 동작 그대로)을 추가하고 공개교육 탭만 `"open-"`을 넘겼다 — 실측 **중복 id 0건**.

- **⚠️ 배지를 `<span>`으로 두면 햄버거 3선 규칙에 눌린다** — `.hamb span{width:24px;height:2px}`이 특이도 (0,1,1)로 `.new-badge`(0,1,0)를 이겨 배지가 **18×18 원이 아니라 24×4 막대**로 렌더됐다(실측). `.nav.solid .hamb span{background:var(--ink)}`까지 겹쳐 배경색도 뺏긴다. 규칙마다 특이도를 올려 쫓아가는 대신 태그를 `<i>`로 바꿔 **선택자 매칭 자체를 끊었다.** 3선의 `span:nth-child(1~3)`은 배지가 4번째 자식이라 영향 없다.
- **⚠️ `transition:visibility .28s`가 포커스 트랩을 죽인다** — 드로어를 열고 `focus()`를 걸어도 포커스가 햄버거에 남았다. 원인은 `visibility`가 전환 진행률 0 지점에서 아직 `hidden`으로 계산되고, **`visibility:hidden` 요소의 `focus()`를 브라우저가 조용히 무시**하기 때문이다(에러도 이벤트도 없다). `requestAnimationFrame` 지연으로도 해결되지 않았다. 처방은 CSS 쪽 — `visibility 0s linear .28s`(닫힘만 지연)로 바꿔 **열 때는 즉시 focusable, 닫을 때는 슬라이드아웃이 끝까지 보이게** 했다. 시각 결과는 종전과 동일하다.
- **스크롤 락은 `overflow:hidden`으로 부족하다** — iOS Safari는 body `overflow:hidden`을 무시하고 배경을 계속 스크롤한다. `position:fixed` + `top:-scrollY`로 들어올리되, 이 방식은 문서 스크롤을 0으로 리셋하므로 닫을 때 저장한 y로 되돌려야 한다. 복원 시 `html{scroll-behavior:smooth}`가 살아 있으면 되돌아가는 과정이 애니메이션으로 보여, **그 순간만 `auto`로 내린다.**
- **포커스 트랩 범위에 햄버거를 포함했다** — 닫기 X는 드로어가 아니라 헤더에 있다. 트랩을 `.mmenu` 내부로만 좁히면 **키보드 사용자가 닫기 수단에 영원히 닿지 못한다.** 순환 첫 항목으로 넣어 마지막(`교육 상담`)에서 Tab → 햄버거로 돌아온다(총 7개 요소).
- **하이드레이션 규칙을 지켜야 배지가 성립한다** — `localStorage`는 서버에 없으므로 초기 상태는 반드시 `false`(배지 숨김)이고, 서버·최초 클라이언트 렌더가 같은 DOM을 만든 뒤 `useEffect`에서만 켠다. M1의 **"마운트 0.6초 뒤 pop" 지연이 이 공백을 그대로 흡수**해, 접근성 타협 없이 불일치 경고 0을 만든다.
- **`localStorage` 접근은 전부 `try/catch`** — 프라이빗 모드·쿠키 차단은 읽기 시점에 **예외를 던진다**. 실패 시 예외를 올리지 않고 "미열람" 기본값으로 되돌린다(알림을 한 번 더 보는 손해가 화면 백지보다 싸다). JSON 파싱 실패·스키마 불일치는 키를 지우고 기본값을 쓴다. 키는 `keess_notice_v1` — 다음 신규 메뉴 알림에서 `_v2`로 올리면 전체가 자연히 초기화된다.
- **신규 토큰은 2개이고 색은 1개뿐** — `--notice:#E5342B`(명세서가 허용한 유일한 추가 색)와 `--ease-pop:cubic-bezier(.2,.8,.2,1)`. 후자는 명세서 지정 이징이 기존 `--ease`·`--ease-out` 어느 것과도 달라, **값 하드코딩 대신 토큰으로 올려 §0-2 "이징은 `var(--*)` 경유"를 지켰다**(색 토큰 아님).
- **배지 모션은 유한 반복** — 0.6s 지연 → pop 220ms → 링 pulse **2회(1.2s) 후 정지**. `animation-iteration-count` 실측 `1, 2`로 무한 반복 0. `prefers-reduced-motion`에서는 전역 reduce 규칙이 duration만 줄이고 **0.6s 지연은 남기므로** 별도 규칙으로 애니메이션을 끄고 즉시 표시·즉시 제거한다.

### 36) 배포 미반영 복구 + 홈 상담 폼 완료 UX 통일 (RD-009 후속)
> `components/sections/home/HomeInquiry.tsx` 1개 파일 수정 + 34)·35) 작업분을 `main`에 병합. 코드 결함 수정이 아니라 **배포 반영 누락 복구 + 범위 확장**이다.

- **배포에 안 나온 이유는 구현 오류가 아니었다** — 34)·35) 커밋 2건이 작업 브랜치에만 있고 `main`에 병합되지 않아, Vercel Production(=`main`) 배포본에 **파일 자체가 없었다.** 병합 전 `main`을 확인한 결과 `hooks/useAutoDismissTimer.ts`·`components/common/InquirySuccess.tsx` 부재, `styles/components.css`의 `done-progress` **0건**. 화면에 안 나오는 게 정상이었다.
- **경위** — 직전 명세서가 "`main`에 직접 푸시하지 말고 PR로 올린다"로 지시했고, 지시대로 브랜치에 푸시한 뒤 **PR 생성이 `gh` CLI 미설치로 실패**해 링크만 안내된 채 병합되지 않았다. 검증은 로컬 `next start`에서만 수행돼 전건 PASS로 보고됐다.

### 35) 모바일 서브내비 — 활성 항목 자동 가로 스크롤 + 오버플로 페이드
> `components/common/SubNav.tsx` + `styles/components.css` 2개 파일. 4개 페이지(`/ax-ai`·`/leadership`·`/hrd`·`/content`)가 이 컴포넌트 하나를 공유해 1곳 수정으로 전부 해결된다.

- **결함** — 스크롤스파이는 정상이었다(활성 클래스·`aria-current` 갱신 정상). 없던 것은 **활성 칩을 가로 스크롤 컨테이너의 가시 영역으로 옮기는 로직**이다. 390px에서 칩이 4개만 보여, 5번째 이후 섹션으로 내려가면 활성 표시가 화면 밖에 있어 "활성 항목이 하나도 없는 내비"가 된다. 그 안에 전환 목표인 `#inq`가 포함된다.
- **정렬 기준은 중앙이 아니라 30%** — 아래로 읽어 내려가는 사용자에게 중요한 정보는 **뒤쪽 항목**이다. 활성 칩 좌변을 컨테이너 폭의 30% 지점에 두면 다음 항목들이 더 많이 보인다. 좌우 24px(`--gut`) 여유를 두고 이미 완전히 보이면 재정렬하지 않아 불필요한 흔들림이 없다.
- **`scrollIntoView` 를 쓰지 않은 이유** — `inline:'center'`에 딸려오는 `block:'nearest'`를 구형 브라우저가 조상 스크롤 컨테이너(=페이지)까지 조정한다. `.subnav`가 sticky라 **페이지가 세로로 튀고 → 스크롤스파이가 재발화 → 재정렬 → 무한 진동**이 된다. `el.scrollTo({left})`로 **가로만** 제어한다.
- **좌표는 `getBoundingClientRect()` 차분으로만** — `.subnav`가 `position:sticky`(=positioned)라 `offsetParent`가 `.subnav-in`이 아니라 `.subnav`가 되어, `offsetLeft` 기반 계산은 `.wrap`의 24px 패딩만큼 어긋난다.
- **사용자 조작이 항상 우선** — 컨테이너의 `pointerdown`·`touchstart`·`wheel` 등 **입력 이벤트만** 1.5초 잠금 트리거로 쓴다. `scroll` 이벤트로 판별하면 **자기 스무스 스크롤이 자기 잠금에 걸려** 자동 정렬이 영구 정지한다. 칩 탭은 잠금을 무시하고 즉시 정렬한 뒤 0.8초 잠금(세로 이동 중 중간 활성 변화로 가로가 딸리는 것 차단).
- **감소 모션은 JS에서 분기** — `globals.css`의 `*{scroll-behavior:auto!important}`는 **명시적 `behavior:'smooth'` API 호출을 막지 못한다.** CSS `scroll-behavior`는 `behavior:'auto'`일 때만 참조되므로 `matchMedia`로 직접 분기한다.
- **페이드는 오버레이가 아니라 `mask-image`** — `.subnav`는 `rgba(255,255,255,.86)`+`backdrop-filter`라 배경색 오버레이를 얹으면 톤이 어긋난다. 게다가 절대 배치 오버레이는 문서 폭을 넓혀 `tests/hero-collision.spec.ts`의 "가로 오버플로 0" 검사를 깨뜨린다. mask로 콘텐츠만 투명하게 만들어 **신규 컬러 토큰 0 · 신규 요소 0**.
- **데스크톱 무변경이 코드로 보장** — `align()`은 `scrollWidth - clientWidth <= 2`면 즉시 return한다. 1280px 4개 페이지 실측 `overflow=0px` · `data-fade="none"` · `mask-image:none` · `scrollLeft=0`.
- **검증**: 390×844에서 4개 페이지를 최상단→최하단 전 구간 스윕(표본 36/38/34/35지점) — **활성칩 최소 가시율 100.0%, 활성 없음 0회, 모든 항목이 활성으로 등장**(9/9/7/6종). 자동 정렬 전후 `window.scrollY` 최대 변화 **0px**(4개 페이지). 한 섹션 정지 5초 관찰 시 `scrollLeft` 고유값 1개(진동 0). 잠금 유지·해제 후 재개, 칩 탭, `#framework` 해시 직입(로드 200ms 시점 이미 정렬), 페이드 3구간(`right`/`both`/`left`), 감소 모션 즉시 이동, 자동 정렬 전후 포커스 불변 — 18항목 전건 PASS. `npx tsc --noEmit` 통과 · `npm run build` 경고·에러 0 · `hero-collision` 8건 PASS.
- ⚠️ 배경 문서는 4개 페이지 항목이 모두 9개라고 봤으나 **실제로는 9/9/7/6개**이며 `/content`는 `SUBNAV`가 아니라 `AXISNAV`를 쓴다. 결함 자체는 오버플로가 생기는 모든 경우에 동일하게 재현되므로 수정 범위는 변하지 않는다.
- ⚠️ 관성 스크롤 충돌·터치 제스처·iOS Safari의 `mask-image` 렌더는 **실기기에서만 확인 가능**하다. iOS Safari · Android Chrome 실기기 확인이 남아 있다.

### 34) 도입문의 완료 카드 — 잔여 시간 프로그레스 바 + 6초 뒤 폼 자동 복귀 (RD-009)
> `hooks/useAutoDismissTimer.ts`·`hooks/usePrefersReducedMotion.ts`·`components/common/InquirySuccess.tsx`·`lib/inquiry/inlineForm.ts` 신설 + `components/sections/{leadership,hrd}/Sections.tsx`·`styles/components.css` 수정. 적용 대상은 `/leadership`·`/hrd` 최하단 **인라인 폼 2곳뿐**이다.

- **결함** — 제출 후 완료 카드가 영구 유지돼 재문의 동선이 끊겼다. 근본 원인은 **"안내 문구가 실제로 일어나지 않는 동작을 예고한 것"**이다. 그래서 이번엔 남은 시간을 문장으로 약속하지 않고 **프로그레스 바로만** 표현했다.
- **사전 조사 — 완료 카드는 공용 컴포넌트가 아니었다** — `/leadership`·`/hrd`(`.form-done`), `/content` 모달(`.okmsg`, 골격 자체가 다르고 닫기 버튼 있음), 홈 `/#inq`(`.form-done`+자체 5초 복귀) **네 곳이 각자 인라인 구현**이었다. 공유 자산은 전역 CSS `.form-done` 하나뿐이라 신규 클래스만 추가하면 회귀가 구조적으로 불가능하다.
- **그럼에도 `autoResetMs` prop(기본값 `null`)로 주입** — 공용 `InquirySuccess`를 새로 두되 자동 복귀를 내부에 하드코딩하지 않았다. 값을 넘기지 않은 호출부는 **코드 변경 0으로 현행 유지**다. 훗날 모달이 이 컴포넌트로 수렴해도 자동 소멸이 번지지 않는다.
- **`setTimeout` 단독 금지 — rAF 누적 경과 시간** — 계측 시작은 제출 시점이 아니라 `IntersectionObserver`로 카드가 **뷰포트 50% 이상 보인 시점**부터다. ① 카드 hover ② `document.hidden` ③ 뷰포트 50% 미만 — 셋 중 하나라도 참인 프레임은 경과에 누적하지 않고, 정지가 풀리면 리셋이 아니라 **남은 시간부터 이어서** 간다.
- **함정 1 — 탭이 숨겨지면 브라우저가 rAF 자체를 멈춘다** — `document.hidden` 분기가 도는 프레임이 없어, 그대로 두면 탭 복귀 첫 프레임에 숨김 구간 전체(수십 초)가 한 번에 누적돼 카드가 즉시 사라진다. `visibilitychange`에서 기준 시각을 즉시 리셋하고, 추가 안전장치로 프레임 델타를 `Math.min(now - last, 100)`으로 클램프했다.
- **함정 2 — `isIntersecting`은 "1px이라도 겹치면 true"** — threshold 이상이라는 뜻이 아니다. 그대로 쓰면 50% 규칙이 무력화되므로 `intersectionRatio >= 0.5`로 판정하고 threshold를 `[0, 0.5]`로 뒀다.
- **hover 정지는 마우스 환경에서만 등록** — 터치 기기는 `pointerleave`가 오지 않아 탭 한 번에 영구 정지될 수 있다. `matchMedia('(hover: hover)')`로 분기했다.
- **완료 카드에 `aria-live`를 걸지 않았다** — live region은 DOM에 먼저 존재한 뒤 내용이 바뀌어야 낭독된다. 내용을 담은 채 통째로 마운트되는 카드는 NVDA·VoiceOver가 읽지 않는 경우가 많다. 낭독은 **phase와 무관하게 항상 DOM에 있는** 시각적 숨김 live region(`.inq-live`)이 맡는다.
- **레이아웃 점프 — 측정 대상과 적용 대상이 같은 요소여야 한다** — 내부 래퍼를 재서 바깥 박스에 적용하면 `box-sizing: border-box`에서 padding·border만큼 낮아져 점프가 남는다. `.inq-shell` 하나를 재고 그 요소에 `minHeight`를 걸고, 카드가 폼보다 짧아도 높이가 유지되도록 같은 박스에 `flex-direction:column; justify-content:center`를 줬다.
- **진행률은 리렌더 없이 DOM에 직접** — `barRef.current.style.transform = scaleX(1-ratio)`. 매 프레임 `setState`는 하지 않는다. `onExpire`는 ref로 최신값을 유지해 콜백 변경이 타이머를 재시작시키지 않게 하고, `finished` 플래그로 정확히 1회만 호출한다.
- **감소 모션에서도 기능은 유지** — 바를 없애지 않고 `quantizeMs=1000`을 넘겨 **1초 단위 6단계로만** 갱신해 연속 애니메이션만 제거했다. 자동 복귀는 그대로다.
- **중복 접수 방지** — 자동 복귀가 빈 폼을 다시 노출하므로 재제출을 유도한다. 정규화한 키(`회사명|담당자|연락처|관심영역|문의내용`)와 타임스탬프를 `useRef`에 두고 **10분 이내 동일 키는 네트워크 호출 없이 차단**, 제출 버튼 위 인라인으로 안내한다.
- **`privacy_agreed` 하드코딩 제거** — 종전 `privacy_agreed: true`를 실제 동의 체크 상태로 바꾸고, `agreed_at`은 제출 시각이 아니라 **체크박스가 체크된 시각**을 보관했다가 쓴다. 복귀 시 이 보관 값도 함께 초기화한다. payload 스키마 자체는 변경 없음.
- **검증**: production build + Chromium 실측 13항목 전건 PASS. 복귀 6485ms(/leadership)·6449ms(/hrd), hover 15초 정지 후 해제 시 남은 시간만 진행(4965ms/기대 4783ms), 다른 탭 20초 후 카드 유지·이어서 진행(2384ms/기대 2200ms), 노출 30%로 15초 완전 정지, **컨테이너 높이 변화 0.03px**, 복귀 후 전 필드·동의 초기화 + `scrollY` Δ0(4회 반복 전건), 동일 내용 재제출 차단·네트워크 요청 0건, 감소 모션 바 단계 정확히 6개. 금지 문자열 5종이 leadership/hrd HTML + 클라이언트 청크 13개씩에서 **0건**. `/content` 모달은 9초 후에도 완료 카드·닫기 버튼 유지, 홈 완료 UX 회귀 0. `next build` 경고·에러 0.
- ⚠️ **제출 payload는 네트워크 탭으로 확인하지 못했다.** 이 두 폼은 백엔드가 없어(§0-6) payload가 연동 슬롯으로만 존재하고 HTTP 요청 자체가 발생하지 않는다. `privacy_agreed`·`agreed_at`은 코드 레벨로만 확인했으며, 실제 검증은 API가 붙은 뒤에 가능하다.
- ⚠️ 이 두 폼에는 **허니팟 필드가 없다**(홈 폼에만 있음). 초기화 대상이 없어 해당 항목은 무동작이다.
- ⚠️ 홈 `/#inq`의 `잠시 후 문의 폼으로 돌아갑니다` 문구는 **의도적으로 남겼다.** 홈 상담 폼은 변경 금지 대상이라 손대지 않았고, 금지 문자열 0건 기준은 leadership·hrd 경로 산출물에 한정된다.

- **mailto는 제목만 프리필** — `[KEESS] 교육 상담 문의`만 싣고 회사명·담당자명·연락처·문의 내용은 body에도 쿼리에도 넣지 않는다. **URL과 메일 클라이언트 이력에 개인정보가 남기 때문**이다. 연락처는 버튼이 아니라 작은 텍스트 1줄이고 이메일이 전화번호보다 앞이다(담당 부서 방침).
- **사전 경고는 막지 않는다** — `문의 내용`에 `<script`·`onerror=`·`javascript:`·`<iframe`·`<img`+`src=`가 보이면 필드 하단에 안내만 띄운다. 오탐 가능성이 있어 **입력도 제출 버튼도 잠그지 않는다**(`aria-describedby`로 연결). 문구는 **차단 결과 화면과 동일한 2줄**로 맞췄다 — 제출 전후로 같은 말을 들어야 무엇을 고쳐야 할지 헷갈리지 않는다.
- **검수자가 직접 재현할 수 있다** — `NEXT_PUBLIC_INQUIRY_MOCK=1`인 기준환경에서 `<script>alert('XSS')</script>`를 실제로 입력하면 차단 화면이 뜬다. `?__inqState=success|blocked|error`로 상태를 강제할 수도 있다. mock은 동적 import라 **운영 빌드의 실행 경로·초기 번들에서 빠진다**.
- **기존 성공 화면은 손대지 않았다** — 확정 카피·`새 문의 작성` 버튼·5초 자동 복귀가 이미 있어, 명세의 "액션 없음/자동 닫힘 없음"과 충돌한다. 정상 동작 코드를 덮지 않는 원칙에 따라 유지하고 신설 2종만 추가했다(lucide 아이콘도 신설 화면에만).
- **검증**: QA 17항목 실측 PASS(제출 중 `aria-busy`+disabled · 차단/실패 화면 문구·용어 금칙 0건 · mailto 입력값 유출 0 · `tel:` 링크 · 입력값 보존 7필드 · 상태 강제 3종 · 인라인 경고 시 제출 버튼 활성 · 일반 특수문자는 경고 없이 성공 · 결과 카드 `role="status"` 포커스 이동 · reduced-motion). `tsc --noEmit` 0 · `next build` 경고 0.

### 28) 과정 리스트 다운로드 모달 — 진행률 표시 + 완료 시 자동 닫힘
> 기준: `KEESS_과정리스트다운로드_모달_자동닫힘_기술명세서_v1.0_260813.md`. `components/sections/content/ContentModals.tsx` + `lib/download/` 신설 4파일 + `data/content.ts`·`styles/content.css`·`components/common/Modal.tsx`.

- **`<a download>`는 완료 시점을 알려주지 않는다** — 그래서 `fetch` + `ReadableStream`으로 청크를 세며 받아 **전송 완료를 직접 감지**하고, 그때 Blob으로 저장을 트리거한다. 16MB 파일이라 LTE에서 5~15초가 걸리는데, 종전에는 "다운로드가 시작됩니다" 한 줄로 그 시간을 견뎌야 했다.
- **`done`에서만 자동으로 닫힌다** — `error`·`preparing`·`downloading`에서는 절대 닫지 않는다. 실패 화면이 저절로 사라지면 무슨 일이 있었는지 알 수 없다.
- **손을 대면 타이머가 풀리고 다시 걸리지 않는다** — 모달에 `pointerenter`·`focusin`·`click`이 오면 즉시 해제한다. 읽는 중에 화면이 사라지는 것이 자동 닫힘의 유일한 실패 모드다. `잠시 후 닫힙니다` 문구와 2px 카운트다운 바로 예고하고, `닫기` 버튼은 항상 둔다.
- **`revokeObjectURL`은 10초 뒤에** — `click()` 직후 즉시 해제하면 일부 브라우저에서 **아직 시작되지 않은 저장이 취소된다**.
- **iOS·저메모리는 아예 다른 길로** — 16MB Blob 조립은 iOS Safari에서 신뢰도가 낮아, `canUseBlobDownload()`가 false면 직접 링크로 저장하고 2.5초 뒤 닫는다(진행률·완료 감지 없음).
- **스피너를 0.3초 늦게 띄운다** — 응답이 빠르면 스피너가 깜빡이고 끝난다. 0.3초 이상 걸릴 때만 화면을 바꾼다.
- **저장 파일명은 기준월을 그대로 달고 나간다** — 명세의 고정 파일명 대신 기존 `downloadFileName`(DF-021-B) 규칙을 유지했다. 화면에서 뺀 시점 표기가 사는 곳이 파일명이기 때문이다.
- **검증**: QA 12항목 실측 PASS(진행률 37샘플 0→100 단조 증가 · 완료 후 1,237ms 자동 닫힘 · hover 시 2.5초 경과에도 유지 · 취소 시 부분 파일 미저장 · 차단 시 error 유지·3회 실패 후 직접 내려받기만 · directMode 2,470ms · 저장 xlsx 원본과 바이트 일치 · 포커스 트리거 복귀 · 재진입 초기화). `tsc --noEmit` 0 · `next build` 경고 0.
- ⚠️ 스크린리더 진행률은 0·25·50·75%까지 읽히고 **100%는 완료 알림에 즉시 덮인다**(같은 렌더 배치). 완료 안내 1회는 정상 동작한다.

### 26) 상담 폼 첨부파일 삭제·교체 기능
> 기준: `KEESS_상담폼_첨부파일관리_기술명세서_v1.0_260812.md`. `components/sections/home/HomeInquiry.tsx` + `styles/components.css`. 백업 태그 `backup/file-attach-7571a98`.

- **문제**: 파일을 한 번 고르면 화면에 취소 수단이 없었다. 민감정보 유의 문구를 띄워두고 **철회 경로를 주지 않은 상태**여서, 잘못 올린 파일을 되돌리려면 새로고침해 폼 전체 입력을 버려야 했다.
- **`input.value` 초기화가 이 기능의 전부다** — `<input type="file">`은 값이 같으면 `change`를 발화시키지 않는다. 상태만 `null`로 두면 "삭제는 되는데 같은 파일 재첨부가 안 되는" 더 나쁜 결함이 된다. 초기화 지점은 **① 삭제 ② 검증 실패 ③ 제출 성공 후 폼 초기화** 3곳이며, 여기에 더해 **선택창을 여는 `openPicker`에서도 선비워** '변경'으로 같은 파일을 골라도 반영되게 했다(총 4곳).
- **취소가 삭제로 동작하던 버그** — 기존 `takeFile(undefined)`가 `resetFile('')`을 불러, 빈 `change`가 오면 첨부가 지워졌다. early return으로 바꿔 **선택창 취소 시 기존 첨부를 유지**한다.
- **3-state** — Selected만 `.file-chip`(파일명·용량·`변경`·`×`)으로 바꾸고 **Empty/Error는 기존 드롭존을 그대로 뒀다.** 문구·높이·드래그&드롭이 무변경으로 남는다. 칩을 `<label>`이 아닌 `<div>`로 둔 이유는, label 안의 버튼을 누르면 삭제 버튼이 파일 선택창을 열어버리기 때문이다.
- **좁은 폭 우선순위** — 컨트롤은 `flex:0 0 auto`로 고정하고 파일명만 말줄임한다. 컨트롤이 먼저 잘리면 삭제 수단 자체가 사라진다. 360px에서 `변경` 53×44 · `×` 44×44 유지 확인.
- **접근성** — `aria-label`(`첨부파일 변경` / `첨부파일 {파일명} 삭제`), 아이콘 `aria-hidden`, 상태 변경 `aria-live="polite"` 안내, 오류 `role="alert"`, 버튼 전건 `type="button"`(생략 시 폼이 제출된다). 삭제 후 포커스가 `body`로 튀지 않도록 드롭존에 `tabIndex={-1}`을 주고 다음 프레임에 포커스를 옮긴다.
- **검증(F5)은 수정하지 않았다** — 확장자·10MB 검사와 오류 문구가 이미 명세와 동일하고 `resetFile`이 이미 `input.value`를 비우고 있었다. 명세 §7 "이미 동일하게 동작하면 수정하지 않는다"에 해당.
- **공통 컴포넌트라 전수 반영** — 첨부 필드를 가진 폼은 `HomeInquiry` 하나뿐이고 홈 `/#inq`와 `/kium` 두 페이지에서 렌더된다. `/leadership`·`/hrd`의 간이 폼과 `/content`에는 첨부 필드가 없고, `/ax-ai`는 자체 폼 없이 홈으로 일원화돼 있다.
- **검증**: 브라우저 회귀 **54/54 PASS** — 최우선 항목인 **삭제 후 동일 파일 재선택** 포함(홈·`/kium` 양쪽), 취소 시 유지, 검증 3종, 키보드 Tab/Enter, 삭제 시 다른 입력값 영향 0, 제출 성공 후 Empty 복귀, 360/768/1440 컨트롤 미잘림, 콘솔 에러 0. `tsc --noEmit` 0 · `next build` 경고 0.
