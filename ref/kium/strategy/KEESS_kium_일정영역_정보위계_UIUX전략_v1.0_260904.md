## 1. 검토 배경

v2.0에서 **중복 노출 제거**를 목표로 「전체 일정」을 전개(add)에서 교체(swap)로 바꿨다.
컨테이너 단위의 중복은 해소됐으나, **컨테이너 안쪽의 정보 중복**은 남아 있었다.
이번 검토는 **일정 영역 내부의 정보 위계**를 대상으로 한다.

> 지면의 문제는 "무엇을 보여줄까"가 아니라 **"같은 사실을 몇 번 말하는가"** 다.
> 한 화면에서 같은 값이 세 번 나오면, 세 번째 값은 정보가 아니라 잡음이 된다.

## 2. 진단

### 2-1. 「11월 6개 회차」 — 한 화면에 3회

`?month=11` 상태에서 같은 수치가 세 곳에 나온다.

| # | 위치 | 표기 | 이 요소의 **역할** | 전체 필터 | **단일 월 필터** |
| --- | --- | --- | --- | --- | --- |
| ① | 기간 필터 칩 | `11월 6회차` | **선택지의 규모** — 다른 월과 비교해 고르는 근거 | 유효 | **유효** |
| ② | 모드 헤더 | `공개교육 일정 · 11월 6개 회차` | **현재 결과** — 필터 적용 후 몇 건인지 | 유효 | **유효** |
| ③ | 월 그룹 헤더 | `11월 6개 회차` | **그룹 구분자** — 스크롤 중 "지금 몇 월" | 유효 | **무효** |

**핵심은 ③의 역할이 필터 상태에 따라 달라진다는 것이다.**

- 전체(20건) 보기 → 10·11·12월 세 그룹이 이어지므로 **구분자가 반드시 필요**하다.
  스크롤 중 sticky 헤더가 "지금 11월"을 답한다.
- 단일 월 보기 → 그룹이 **하나뿐**이라 구분할 대상이 없다. 건수는 ②가 이미 말했다.
  → **역할이 0인 채 자리만 차지한다.**

> ①을 지우는 선택지는 없다. 필터 컨트롤은 "고르기 전"의 정보이고,
> 헤더는 "고른 뒤"의 정보다. 시점이 다르므로 중복이 아니다.

**→ ③을 조건부로 없앤다.** 무조건 제거하면 전체 보기에서 20건이 구분 없이 흐른다.

### 2-2. 뷰를 바꾸면 기능이 사라진다

같은 회차 데이터인데 요약(스트립)과 전체(리스트)의 과정명 동작이 다르다.

| 항목 | 간략히 보기 (스트립 카드) | **전체 일정 (리스트 행)** |
| --- | --- | --- |
| 요소 | `<button class="kium-scard2-course">` | `<span class="kium-srow-title">` — **정적** |
| hover 단서 | 색 변화 + 밑줄 복원 | **없음** |
| focus 단서 | `:focus-visible` 동일 | **없음** (포커스 대상 아님) |
| 클릭 | 그리드 카드로 스크롤 + 확장 + 2초 하이라이트 + 포커스 | **없음** |
| 접근명 | `{과정명} 과정 카드로 이동` | 없음 |

BT-18에서 두 뷰를 **같은 자리에서 토글로 교체**되게 만들었기 때문에 이 불일치가 특히 드러난다.
사용자는 토글 하나를 눌렀을 뿐인데 **조금 전까지 되던 동작이 사라진다.**

> 요약과 전체의 관계는 '깊이'이지 '다른 기능'이 아니다.
> 전체는 요약의 **상위집합**이어야 한다 — 정보도, 동작도.

### 2-3. 상수 라벨의 반복 — 「1인 기준」

- 리스트 20행 × `1인 기준` = **20회 반복**
- 공개교육 9과정 **전건 동일 기준**이다. 과정별로 다른 값이 없다.
- 라벨은 **값이 갈릴 때** 정보가 된다. 전건 같은 값은 **행마다 반복할 이유가 없다.**

> 판단 기준: "이 라벨을 지우면 어떤 행의 의미가 달라지는가?"
> 답이 '없음'이면 그 라벨은 행 단위가 아니라 **영역 단위**에 속한다.

### 2-4. ★ 신규 발견 — 전체 일정의 날짜가 오름차순이 아니다 (P0)

`SessionListView`는 `sortByWeight`(**weight ASC → start ASC**)로 정렬한다.
`KIUM_SESSION_META`의 weight는 `confirmed 1 · closing 1 · recruiting 2 · closed 4`다.

전건 `recruiting`이던 동안에는 weight가 모두 같아 **결과적으로 날짜순**이었다.
**회차 상태 시드가 적용되는 순간 날짜가 뒤섞인다.**

| 월 | 현재 렌더 순서 (시드 적용 후) |
| --- | --- |
| 10월 | 10.12 · 10.14 · 10.21 · 10.26 · **10.19** · 10.27 |
| 11월 | 11.2 · 11.12 · 11.16 · 11.17 · **11.9** · 11.18 |
| 12월 | 11.30 · 12.7 · 12.11 · 12.14 · **12.9** · 12.16 · 12.17 · 12.21 |

11월의 `11.9`는 제자리보다 **네 칸 뒤**로 밀린다.

**왜 결함인가**

- 이 화면의 이름이 「전체 **일정**」이다. **시간 축**이 축이다.
- 사용자의 과업은 "내가 되는 날짜에 뭐가 있나"를 훑는 것이다. 날짜가 튀면 훑기가 성립하지 않는다.
- 스트립은 순수 날짜 오름차순이다. **같은 자리 토글로 교체되는 두 뷰의 순서가 서로 다르다.**
- 상태 우선 정렬은 '추천순'의 논리다. 월 그룹으로 묶인 날짜 목록에는 맞지 않는다.

**단, `마감`은 예외다.** 지난 회차가 미래 회차 사이에 끼면 그것대로 훑기를 방해한다.
→ **`closed`만 뒤로, 나머지는 순수 날짜순**이라는 2단 정렬이 정답이다.

## 3. 설계 원칙

| # | 원칙 | 적용 |
| --- | --- | --- |
| P1 | **한 사실은 한 번만** — 단, 역할이 다르면 중복이 아니다 | 필터 칩(고르기 전) ≠ 헤더(고른 뒤) → 둘 다 유지. 그룹 헤더는 역할이 사라질 때만 제거 |
| P2 | **전체는 요약의 상위집합** — 정보도 동작도 | 리스트 과정명에 스트립과 동일한 동작 부여 |
| P3 | **전건 동일한 값은 항목이 아니라 영역에 속한다** | `1인 기준`을 행에서 걷어 컨테이너 헤더로 |
| P4 | **축이 이름을 결정한다** — 「일정」이면 시간 축이 1순위 | 리스트 정렬을 날짜 오름차순으로 |
| P5 | **옵션 prop으로 확장** — 미지정 시 기존 렌더 무변경 | 숨김 보존된 `KiumSchedule`의 A type 렌더를 깨뜨리지 않는다 |

## 4. 확정 전략

### R1. 월 그룹 헤더 — 단일 월 필터에서 미렌더

| 항목 | 내용 |
| --- | --- |
| 조건 | 기간 필터가 **단일 월**(그룹이 1개)일 때만 헤더 미렌더 |
| 유지 | 전체 필터(그룹 2개 이상)에서는 현행 그대로 — sticky 구분자 필요 |
| 판정 기준 | **렌더된 그룹 수**로 판정한다(필터 값이 아니라). 데이터가 바뀌어도 규칙이 성립한다 |
| 접근성 | 헤더가 없으면 `aria-labelledby` 참조가 깨진다 → `aria-label="{N}월 회차 목록"`으로 대체 |
| 여백 | 헤더가 빠진 만큼 상단 여백을 컨테이너 본문 패딩이 흡수하게 조정 |

### R2. 리스트 과정명 — 스트립과 동일한 동작

| 항목 | 내용 |
| --- | --- |
| 동작 | hover·focus 단서 + 클릭 시 그리드 카드로 스크롤 + 확장 + 2초 하이라이트 + 포커스 |
| 구현 | `onCourseFocus` **옵션 prop** — 미지정 시 정적 `<span>` 유지(P5) |
| **색** | 기본 `--ink` 유지 · hover·focus에서만 `--p1` + 밑줄 |
| 색 근거 | 스트립은 6장이라 `--p1`이 괜찮았다. **리스트는 20행**이라 기본 상태를 보라로 칠하면 지면이 시끄럽다. 리스트에서 과정명은 이미 가장 큰 텍스트(15px/800)라 색 없이도 위계가 선다 |
| 터치 타깃 | `.kium-scard2-course`와 같은 방식으로 히트 영역 44px 확보(레이아웃 불변) |
| 리스트 접힘 | **접지 않는다** — 사용자가 연 상태를 시스템이 되돌리지 않는다. 다시 일정으로 돌아올 때 펼침이 유지돼야 자연스럽다 |
| 툴팁 | **만들지 않는다** — hover 툴팁은 터치 기기에서 발화하지 않아 접근 경로가 갈린다. 클릭 → 카드 확장이 모든 입력 수단에서 동일하게 동작하는 유일한 답이다 |

### R3. 「1인 기준」 — 영역 헤더에 1회

| 위치 | 조치 |
| --- | --- |
| 리스트 행 `.kium-srow-meta` | **제거** (20회 → 0회) |
| 모드 헤더 보조 문구 | `1명부터 신청 가능` → **`1명부터 신청 가능 · 교육비 1인 기준`** |
| 상세 패널 pill | **유지** — 한 과정만 보는 화면이라 반복이 아니고, 딥링크로 바로 들어온 사용자에겐 이곳이 유일한 고지처다 |
| `KIUM_PRICE_NOTE` 상수 | **유지** — 문구 출처를 한 곳으로 둔다. 헤더와 상세 패널이 같은 상수를 참조 |

### R4. 리스트 정렬 — `closed` 뒤로 · 나머지 날짜 오름차순

| 항목 | 내용 |
| --- | --- |
| 규칙 | 1차 `closed ? 1 : 0` ASC → 2차 `start` ASC |
| 효과 | 스트립(순수 날짜순)과 순서가 일치 → 토글 교체 시 순서가 흔들리지 않는다 |
| `sortByWeight` | **함수 무변경** — `CourseListView`·`KiumSchedule`이 참조한다. `SessionListView`에서 정렬만 교체 |

| # | 항목 | 판단 |
