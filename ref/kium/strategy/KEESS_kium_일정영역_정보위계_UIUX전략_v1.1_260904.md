## 1. 검토 배경

v2.0에서 **중복 노출 제거**를 목표로 「전체 일정」을 전개(add)에서 교체(swap)로 바꿨다.
컨테이너 단위의 중복은 해소됐으나 **컨테이너 안쪽**은 남아 있었다(v1.0 R1~R4).

v1.1은 여기에 **회차 상태 시드가 배포되면서 처음 드러난 문제**를 더한다.
전건 `모집중`이던 동안에는 `상담하기` 한 종류만 렌더돼 보이지 않던 것들이다.

## 2. 진단

### 2-1. 「11월 6개 회차」 — 한 화면에 3회

`?month=11` 상태에서 같은 수치가 세 곳에 나온다.

| # | 위치 | 표기 | 역할 | 전체 필터 | **단일 월** |
| --- | --- | --- | --- | --- | --- |
| ① | 기간 필터 칩 | `11월 6회차` | 선택지의 규모 (고르기 **전**) | 유효 | **유효** |
| ② | 모드 헤더 | `공개교육 일정 · 11월 6개 회차` | 현재 결과 (고른 **뒤**) | 유효 | **유효** |
| ③ | 월 그룹 헤더 | `11월 6개 회차` | 그룹 구분자 | 유효 | **무효** |

③의 역할이 필터 상태에 따라 달라진다. 전체(20건)에서는 세 그룹이 이어지므로 sticky 구분자가 필수이나, 단일 월에서는 구분할 대상이 없고 건수는 ②가 이미 말했다.
→ **조건부로 없앤다.** ①은 "고르기 전", ②는 "고른 뒤"라 시점이 달라 중복이 아니다.

### 2-2. 뷰를 바꾸면 기능이 사라진다

| 항목 | 간략히 보기 (스트립) | **전체 일정 (리스트)** |
| --- | --- | --- |
| 요소 | `<button class="kium-scard2-course">` | `<span class="kium-srow-title">` — **정적** |
| hover·focus 단서 | 색 + 밑줄 복원 | **없음** |
| 클릭 | 그리드 카드로 스크롤 + 확장 + 2초 하이라이트 | **없음** |

BT-18에서 두 뷰를 **같은 자리 토글 교체**로 만들었기에 불일치가 특히 드러난다.
요약과 전체의 관계는 '깊이'이지 '다른 기능'이 아니다 — 전체는 요약의 **상위집합**이어야 한다.

### 2-3. 상수 라벨의 반복 — 「1인 기준」

리스트 20행 × `1인 기준` = 20회. 공개교육 9과정 **전건 동일**하다.
판단 기준: *"이 라벨을 지우면 어떤 행의 의미가 달라지는가?"* → 답이 '없음'이면 **행이 아니라 영역**에 속한다.

### 2-4. 전체 일정의 날짜가 오름차순이 아니다 (P0)

`sortByWeight`는 **weight ASC → start ASC**이고 weight는 `confirmed 1 · closing 1 · recruiting 2 · closed 4`다.
전건 `recruiting`이던 동안에는 결과적으로 날짜순이었으나, **시드 적용 순간 뒤섞인다.**

| 월 | 시드 적용 후 순서 |
| --- | --- |
| 10월 | 10.12 · 10.14 · 10.21 · 10.26 · **10.19** · 10.27 |
| 11월 | 11.2 · 11.12 · 11.16 · 11.17 · **11.9** · 11.18 |
| 12월 | 11.30 · 12.7 · 12.11 · 12.14 · **12.9** · 12.16 · 12.17 · 12.21 |

「전체 **일정**」은 시간 축이다. 상태 우선 정렬은 '추천순'의 논리이고 월 그룹 날짜 목록에는 맞지 않는다.
스트립은 순수 날짜순이므로 **토글로 교체되는 두 뷰의 순서가 어긋난다.**

### 2-5. ★ v1.1 — 회차 카드 CTA 줄밀림 (P0)

`마감임박` 카드에서 `마감 전 상담`이 `마감 전 상 / 담`으로 **2줄로 깨진다.**

**폭 계산 (PC 최소 카드)**

| 항목 | 값 |
| --- | --- |
| `.kium-ustrip{grid-auto-columns:minmax(212px,1fr)}` | 카드 최소 **212px** |
| − `.kium-scard2` padding 16 × 2 | 카드 내부 **180px** |
| − `.kium-sact` padding 12 × 2 + border 2 | 버튼 내부 **154px** |

| 상태 | 좌(상태) | gap | 우(동작) | 합계 | 판정 |
| --- | --- | --- | --- | --- | --- |
| `마감임박` | `⏰ 마감임박` ≈ 71 | 10 | `마감 전 상담 →` ≈ 98 | **179px** | 154 초과 → **줄바꿈** |
| `개강확정` | `✓ 개강확정` ≈ 71 | 10 | `상담하기 →` ≈ 72 | **153px** | 154 이내 → **1px 여유** |

**두 가지가 동시에 드러난다.**

**① 라벨이 상태를 두 번 말한다 (근본 원인)**
`마감 전 상담`의 '마감 전'은 **좌측 `마감임박` 배지와 같은 사실**이다.
v2.0 BT-17에서 이 문구를 축약하지 않은 근거는 *"문구 자체가 상태 정보를 진다"* 였는데,
그때는 **배지와 CTA가 분리**돼 CTA 라벨이 단독으로 읽히는 맥락이었다.
BT-20에서 배지를 버튼 **안으로** 흡수한 뒤로 전제가 바뀌었다 —
**좌측이 상태를, 우측이 동작을 말하는 구조**에서 우측이 상태를 다시 말할 이유는 없다.

**② 라벨을 통일해도 여유가 1px뿐이다 (구조 결함)**
`상담하기`로 통일하면 153px로 들어가지만 **한 자리 수 여유**다.
폰트 렌더링 편차 · 브라우저 확대 · 잔여석 표기(`마감임박 잔여 3석`)가 붙으면 **즉시 다시 밀린다.**
현재 `.kium-sact-st{flex:none}`이고 `.kium-sact-go`에 `white-space:nowrap`이 없어
**넘치면 우측 라벨이 줄바꿈되는 것이 기본 동작**이다.

> 라벨 통일은 **원인**을 없애고, 폭 방어는 **재발**을 막는다. 둘 다 필요하다.

### 2-6. ★ v1.1 — 스트립 카드 CTA 하단 정렬 누락 (BT-20 이월)

```css
.kium-ustrip .kium-scard2 .kium-cta-ses,
.kium-ustrip .kium-scard2 .kium-cta-next{margin-top:auto}
```

BT-20에서 카드의 버튼이 `.kium-sact` / `.kium-sact-closed`로 바뀌었는데
**이 정렬 규칙이 따라가지 않았다.** 두 클래스가 목록에서 빠져 있다.

스트립은 그리드 행이 stretch되어 카드 높이가 최댓값에 맞춰지는데,
`margin-top:auto`가 걸리지 않으면 버튼이 콘텐츠 바로 아래에 붙고 **카드마다 버튼 높이가 어긋난다.**
과정명이 2줄인 카드(`진단 기반 팀장 리더십 Re-Lead 과정`)와 1줄인 카드가 나란히 서면 바로 보인다.

## 3. 설계 원칙

| # | 원칙 | 적용 |
| --- | --- | --- |
| P1 | **한 사실은 한 번만** — 단, 역할이 다르면 중복이 아니다 | 필터 칩 ≠ 헤더 → 유지. 그룹 헤더는 역할이 사라질 때만 제거 |
| P2 | **전체는 요약의 상위집합** — 정보도 동작도 | 리스트 과정명에 스트립과 동일 동작 |
| P3 | **전건 동일한 값은 항목이 아니라 영역에 속한다** | `1인 기준`을 헤더로 |
| P4 | **축이 이름을 결정한다** — 「일정」이면 시간 축이 1순위 | 리스트 날짜 오름차순 |
| P5 | **옵션 prop으로 확장** — 미지정 시 기존 렌더 무변경 | 숨김 보존 `KiumSchedule` 보호 |
| **P6** | **한 요소는 한 가지만 말한다** — 상태는 좌측, 동작은 우측 | CTA 라벨에서 상태 문구 제거 |
| **P7** | **레이아웃은 최악의 콘텐츠를 견뎌야 한다** — 여유 1px은 여유가 아니다 | 줄바꿈을 CSS로 원천 차단 |

## 4. 확정 전략

### R1. 월 그룹 헤더 — 단일 월 필터에서 미렌더

| 항목 | 내용 |
| --- | --- |
| 조건 | **렌더된 그룹 수**로 판정(필터 값이 아니라) — 1개면 미렌더 |
| 유지 | 그룹 2개 이상에서는 현행 그대로 (sticky 구분자 필요) |
| 접근성 | 헤더가 없으면 `aria-labelledby`가 깨진다 → `aria-label="{N}월 회차 목록"` |

### R2. 리스트 과정명 — 스트립과 동일한 동작

| 항목 | 내용 |
| --- | --- |
| 동작 | hover·focus 단서 + 클릭 시 카드 스크롤·확장·2초 하이라이트·포커스 |
| 구현 | `onCourseFocus` **옵션 prop** — 미지정 시 정적 `<span>`(P5) |
| **색** | 기본 `--ink` · hover·focus에서만 `--p1` + 밑줄 |
| 색 근거 | 스트립은 6장이라 `--p1`이 괜찮았다. **리스트는 20행**이라 기본을 보라로 칠하면 시끄럽다. 과정명은 이미 최대 텍스트(15px/800)라 색 없이 위계가 선다 |
| 하지 않음 | hover 툴팁(터치 미발화) · 클릭 시 리스트 자동 접힘(사용자가 연 상태를 되돌리지 않는다) · 행 전체 클릭화 |

### R3. 「1인 기준」 — 영역 헤더에 1회

| 위치 | 조치 |
| --- | --- |
| 리스트 행 | **제거** (20회 → 0회) |
| 모드 헤더 | `1명부터 신청 가능` → **`1명부터 신청 가능 · 교육비 1인 기준`** |
| 상세 패널 pill | **유지** — 한 과정만 보는 화면이라 반복이 아니고, 딥링크 진입 시 유일한 고지처 |

### R4. 리스트 정렬 — `closed` 뒤로 · 나머지 날짜 오름차순

1차 `closed ? 1 : 0` ASC → 2차 `start` ASC.
`sortByWeight` **함수는 무변경**(`CourseListView`·`KiumSchedule`이 참조).

### R5. ★ CTA 라벨 통일 — `마감 전 상담` → `상담하기`

| 상태 | 좌(배지) | 우(동작) | 근거 |
| --- | --- | --- | --- |
| `recruiting` | 모집중 | `상담하기` | 현행 유지 |
| `confirmed` | 개강확정 | `상담하기` | 현행 유지 |
| **`closing`** | 마감임박 | **`상담하기`** | '마감 전'은 좌측 배지와 같은 사실. 긴박감은 **배경색(red tint)**이 진다 |
| `closed` | 마감 | `다음 회차 상담` | **유지** — '다음 회차'는 *다른 회차*를 가리키는 정보이지 상태 반복이 아니다 |

- 정보 손실 없음: 상태는 배지 텍스트 + 아이콘 + 색 + `aria-label`(`… 마감임박 상담하기`)이 4중으로 진다.
- 부수 효과: 우측 라벨이 항상 `상담하기` 4자로 **고정폭**이 되어 카드 간 시각 리듬이 맞는다.
- `CTA_LABEL` **단일 출처 유지** — `SessionCta`(쇼케이스·숨김 히어로)도 같은 값을 쓴다.

> **사용자 제안 중 「라벨 자체를 제거」는 채택하지 않는다.**
> v2.1 §5-5의 통합 근거가 *"'모집중'은 상태(명사)라 버튼 라벨이 동작을 말하지 않는다"* 였다.
> 동작 라벨을 빼면 버튼이 다시 배지로 읽혀 **클릭 가능성이 학습되지 않는다.**
> 화살표(`→`)도 유지한다 — 카드 안 유일한 방향 어포던스이고, 폭 문제는 R6가 구조적으로 푼다.

### R6. ★ 줄바꿈 원천 차단 — 축소 우선순위 명시

| 규칙 | 내용 |
| --- | --- |
| 우측(동작) | `white-space:nowrap` + `flex:none` — **절대 줄바꿈·축소하지 않는다** |
| 좌측(상태) | `flex:0 1 auto` + `min-width:0` + 라벨 말줄임 — **넘치면 좌측이 줄어든다** |
| 여유 확보 | `gap` 10→8 · `padding` 12→10 = **+6px** |
| 근거 | 우측은 이 버튼의 **목적**이다. 좌측 상태는 아이콘·색으로도 부호화돼 있어 텍스트가 줄어도 판독이 유지된다 |

확보 후 폭: 버튼 내부 **158px** vs 필요 **151px** → **7px 여유**(현행 1px 대비 7배).

### R7. ★ 스트립 카드 CTA 하단 정렬 복구

`margin-top:auto` 규칙에 `.kium-sact` · `.kium-sact-closed`를 추가한다.
BT-20에서 버튼 클래스가 바뀔 때 따라가지 않은 **이월 결함**이다.
