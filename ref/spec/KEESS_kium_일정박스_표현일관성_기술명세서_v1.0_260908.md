## 1. 제기된 문제 (사업 검토, 2026-09-08)

> "모집중·개강확정·마감임박의 「간략히 보기」 상태 UI와 마감일 때의 UI를 왜 다르게 하나? 이 상태면 마감에서는 「간략히 보기」로 전환해도 UI가 동일해서 '뭐가 바뀐 거야? 오류 아니야?' 할 수 있지 않나?"

### 1-1. 실측 재현 (배포본, 2026-09-08)

| 조작 | 토글 라벨 | `.kium-scard2`(카드) | `.kium-srow`(리스트 행) | 화면 |
| --- | --- | :--: | :--: | --- |
| 모집 상태 `전체` | `전체 일정 20개 회차` | **6** | 0 | 스트립 |
| `마감 1` 선택 | `전체 일정 1개 회차` | **0** | **1** | 리스트 |
| 위에서 토글 1회 클릭 | `간략히 보기` | 0 | 1 | **동일** |
| 토글 1회 더 클릭 | `전체 일정 1개 회차` | 0 | 1 | **동일** |

### 1-2. 문제의 정체 (2건)

**P1. 같은 축에서 값만 바꿨는데 표현 문법이 바뀐다**

「모집 상태」는 **데이터 값을 고르는 축**이다. `개강확정`을 고르면 카드 스트립, `마감`을 고르면 세로 리스트가 나온다면, 사용자는 자기가 고른 것이 값인지 화면 모드인지 알 수 없다. 필터는 목록을 거르는 것이지 **화면 문법을 바꾸는 컨트롤이 아니다.**

**P2. 토글이 죽은 컨트롤이 된다**

`마감` 상태에서 토글은 노출되고 라벨도 바뀌지만 **화면은 그대로다.** 눌러도 아무 일이 없는 컨트롤은 사용자에게 오류로 읽힌다. 검수자에게는 결함 리포트 대상이 된다.

**P3. Empty Case 검토 칩이 사실상 미반영 상태다**

F23으로 `Empty Case` 칩을 넣었으나 `?preview` 쿼리 게이트 뒤에 있다. 실측 결과 `?preview=cases`에서만 `.kium-chip-review` 1개가 렌더되고, 일반 URL에서는 DOM에 존재하지 않는다. 이 배포본은 **디자이너·개발자가 보는 기획서**인데, 쿼리를 아는 사람만 볼 수 있으면 "반영되지 않았다"로 인지된다. 실제로 사업 검토에서 그렇게 보고되었다.

### 1-3. 원인

F24가 「스트립이 0장이면 그 자리에 리스트를 렌더」하는 **폴백**으로 문제를 우회했기 때문이다. 일정 박스는 원래 **표현 모드 2종**(간략히 = 스트립 / 전체 일정 = 리스트)을 토글로 오가는 구조인데, 폴백이 그 위에 **데이터 조건에 따른 세 번째 상태**를 끼워 넣어 토글과 충돌했다.

**근본 원인은 스트립이 `closed`를 표현하지 못한다는 제약**이고(F0-9), 폴백은 그 제약을 우회한 것이다. 제약 자체를 없애는 것이 옳다.

## 4. 변경 명세

### F27 (핵심) 스트립 소스 규칙 단일화

스트립 소스에서 **`closed` 제외 조건을 삭제**한다(H4 폐기).

```
변경 전: 미래 회차(end >= today) AND effectiveStatus !== 'closed' AND 필터 적용
변경 후: 미래 회차(end >= today) AND 필터 적용
```

- 정렬: `start ASC` (상태와 무관한 단일 날짜순). 상태별 우선순위 정렬 **금지**
- 미래 회차 조건(`end >= today`)은 **유지**한다. 스트립에 들어오는 `closed`는 "날짜는 남았으나 정원이 찬 회차"뿐이며, 날짜가 지나 자동 승격된 회차는 이 조건에서 이미 제외된다
- 노출 수 규칙(PC/TB 6장 · MO 3장), 스냅·peek, 필터 연동 갱신 **무변경**

**적용 결과 (모집 상태 전체 기준)**

| 순번 | 변경 전 (H9) | 변경 후 |
| --- | --- | --- |
| 1 | 10.12 마감임박 | 10.12 마감임박 |
| 2 | 10.14 개강확정 | 10.14 개강확정 |
| 3 | 10.19 모집중 | 10.19 모집중 |
| 4 | 10.26 마감임박 | **10.21 마감** |
| 5 | 10.27 모집중 | 10.26 마감임박 |
| 6 | 11.02 개강확정 | 10.27 모집중 |

> F21이 보존하려던 「MO 3장 3상태 커버리지」(10.12·10.14·10.19)는 그대로 유지된다. PC 6장에서 11.02가 밀려나지만 3상태 커버리지는 유지되며, 이는 검토 편의 항목이므로 사업 요구가 우선한다.

### F28 스트립 마감 카드 표현

`.kium-scard2`가 `closed`를 렌더할 수 있게 한다. **CSS는 이미 준비되어 있다**(H5).

| 요소 | 규격 |
| --- | --- |
| 카드 속성 | `data-status="closed"` 부여 → 기존 `opacity:.72` 자동 적용 |
| 상태 배지 | 기존 `SessionBadge` 마감 규격 그대로 |
| CTA | `상담하기` 대신 **`다음 회차 상담`** |
| CTA 동작 | 프리필 경로 B, 문안 H7과 **완전 동일** (리스트 행과 같은 결과) |
| 날짜·과정명·일수 | 다른 상태 카드와 동일 레이아웃. 마감 전용 레이아웃 신설 금지 |

- 리스트 행의 `.kium-sact-closed`와 **동일한 액션 컴포넌트를 재사용**한다. 카드 전용 마감 액션을 새로 만들지 않는다
- 카드 1장 안에서 CTA 영역이 2행으로 늘어나지 않아야 한다(리스트 행 1행 유지 규칙의 카드판)

### F29 F24 폴백 제거, 토글 실효 복원

- `.kium-schedbox-body`의 **3분기 폴백(F24)을 삭제**하고 원래 2분기로 되돌린다

| 조건 | 렌더 |
| --- | --- |
| `visible.length === 0` | 빈 상태(F26 문구 유지) |
| 토글 접힘 | **스트립** (F27 소스) |
| 토글 펼침 | `.kium-slist` (필터 적용된 `visible`) |

- 토글은 **어떤 필터 조합에서도 스트립 ↔ 리스트를 실제로 전환**해야 한다. 라벨만 바뀌고 내용이 같은 상태가 0건이어야 한다
- F24가 추가한 폴백 전용 `aria-live` 안내(`조건에 맞는 회차 {n}건을 일정 목록으로 표시했습니다`)는 **삭제**한다. 토글 전환 안내는 기존 규칙 사용
- 토글 라벨 규칙(H3) 무변경

### F30 Empty Case 검토 칩 상시 노출 (게이트 해제)

이 배포본은 고객 화면이면서 **동시에 기획서**다(F21 §1). 0건 상태의 화면을 디자이너·개발자가 **URL을 몰라도** 확인할 수 있어야 한다.

**변경**

| 항목 | 변경 전 (F23) | 변경 후 |
| --- | --- | --- |
| 노출 조건 | `?preview` 쿼리가 있을 때만 | **상시 노출** (상수 제어) |
| 위치 | 모집 상태 칩 행 맨 끝 | **동일** (모집 상태 칩 행 맨 끝) |
| 라벨 | `Empty Case` | 동일 |
| 시각 구분 | 점선 테두리 `.kium-chip-review` | 동일 |
| 카운트 · `data-st` | 미표기 · 미부여 | 동일 |

> 사업 검토 표현인 **「마감임박 우측」**은 이 규칙에 포함된다. F22(0건 칩 미노출)로 기간 `11월`·`12월`에서는 마감 칩이 사라지므로, 「행 맨 끝」은 그 조건에서 실제로 마감임박 칩의 우측이 된다. 위치를 특정 칩에 고정하지 않고 **행의 마지막**으로 두는 편이 F22와 충돌하지 않는다.

**노출 제어 (실서비스 배포 전 제거 보장)**

```tsx
/* [F30] 검토용 칩 — 이 배포본은 기획서를 겸하므로 상시 노출한다.
   ★ 실서비스 오픈 전 반드시 false 로 변경할 것. false 면 DOM 자체가 생성되지 않으며,
     ?preview=cases · ?preview=badges 검토 경로는 그대로 살아 있다. */
const SHOW_REVIEW_CHIP = true;
```

- 렌더 조건: `SHOW_REVIEW_CHIP || reviewMode` (`reviewMode`는 F23의 `?preview` 판정 그대로)
- 상수는 **한 곳에만** 선언하고, 선언부 주석에 제거 시점과 방법을 명기한다
- `SHOW_REVIEW_CHIP = false` 시 `.kium-chip-review` **DOM 0건**이어야 한다 (`display:none` 금지)
- `?preview=cases` · `?preview=badges` 동작은 **무변경**으로 보존한다

**릴리즈 게이트 등록**

- 릴리즈 체크리스트에 다음 항목을 A등급으로 추가한다: `실서비스 배포 전 SHOW_REVIEW_CHIP=false 확인, Empty Case 칩 DOM 0건`
