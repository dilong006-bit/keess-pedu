## 1. 고도화 배경 — 현 구현의 구조적 한계

### 1-1. 한계 3가지

1. **전체과정 보기의 상세 패널에 신청 경로가 없다.**
   `공개교육` pill이 회차 날짜를, `교육비` pill이 단가를 노출하지만 **그 정보로 실행할 수 있는 행동이 없다.**
   하단 CTA는 프리필 경로 ①(`[관심 과정: …]`)이라 사용자가 방금 읽은 회차가 상담 폼에 담기지 않는다.

2. **되짚기 비용이 신청 의향 최고점에 부과된다.**
   공개교육으로 신청하려면 ①상단 스크롤 ②세그먼트 전환 ③필터 재적용 ④과정 재탐색 ⑤회차 선택 —
   **클릭 4~5회 + 스크롤 왕복 2회.** 그 과정에서 3단계에서 확정된 의사결정 맥락이 흩어진다.

3. **A/B 비교에서 B안의 강점으로 제시한 명제가 실제로는 성립하지 않는다.**
   > "19과정을 한 화면에서 보며 개설 과정에 표시가 붙습니다. **과정 선택과 신청 방식 선택을 한자리에서 합니다.**"

   현 구현은 **정보만 한 자리이고 행동은 다른 자리**다. 「신청 방식 선택」이 보기 전환을 요구한다.

### 1-2. 방향성

> **"보기를 바꾸지 않고 끝낸다 — 상세 패널이 정보 화면에서 결정 화면이 된다."**

본 증분은 새 기능 추가가 아니라 **B안 설계 의도의 미완성 부분을 완성**하는 것이다.
근거: 필요한 자산(회차 스트립·회차 카드·프리필 경로 A)이 전부 존재하고 `onConsultSession` prop도
이미 전체 보기 경로로 전달되고 있다. 단절은 설계 의도가 아니라 **`variant` 분기의 부작용**이었다.

## 2. 요구사항 분석 — 의도와 목적 해석

### 2-1. 원 요구사항 (verbatim)

> "과정 상세 정보를 조회중일 때 우측 상단에 '공개교육', '교육비'가 노출되는데 여기서도 바로 일정 확인 후 신청을 할 수 (상담폼 이동) 있으면 어떨까요?
> 공개교육 선택을 희망하는 사람이 다시 상단으로 올라가서 공개교육칩을 선택한 후 다시 그 과정을 살펴보는게 아니라 '전체과정'일 때도 바로 스무스하게 이어서 공개교육 일정 확인 후 신청할 수 있는 방법을 자연스럽게 제공하는 것을 제안"

### 2-2. 해석

```
[R1] 전체 보기 상세 패널의 신청 경로 단절
- 표면 요청: 전체과정 보기의 상세 패널에서도 회차 일정을 보고 바로 상담 신청
- 진짜 의도: 보기를 전환하지 않고, 관심이 확정된 그 자리에서 전환을 완료하고 싶다
- 해결 문제: 신청 의향 최고점에서 클릭 4~5회 + 스크롤 왕복 2회의 되짚기를 강요
- 성공한 모습: 전체 보기에서 과정 상세를 연 사용자가 보기를 바꾸지 않고 회차를 골라,
              그 회차가 담긴 채 상담 폼에 도착
```

```
[R2] 정보 중복 — pill 날짜 나열 (도출)
- 표면 요청: (명시 없음 — R1 반영 시 발생하는 부작용)
- 진짜 의도: 한 패널 안에서 같은 사실이 두 번 나오지 않아야 한다
- 해결 문제: 회차 블록 신설 시 `공개교육` pill의 날짜와 블록의 날짜가 중복
- 성공한 모습: pill은 '공개교육으로도 됩니다'라는 사실을, 블록은 날짜라는 값을 각각 한 번씩만 말함
```

```
[R3] CTA 경로 불일치 (도출)
- 표면 요청: (명시 없음)
- 진짜 의도: 같은 과정은 어느 화면에서 보든 같은 신청 방식으로 안내되어야 한다
- 해결 문제: 현행 CTA가 `보고 있는 화면(variant)`으로 분기해,
            공개교육 과정인데 전체 보기에서는 일반 관심 문의(경로 ①)로 빠진다
- 성공한 모습: CTA가 `과정의 신청 방식`으로 분기해 두 보기에서 동일하게 동작
```

```
[R4] 상세 패널 회차 정렬 오류 (도출)
- 표면 요청: (명시 없음 — R1 반영 시 즉시 드러나는 기존 결함)
- 진짜 의도: 한 과정의 회차는 "언제 하는지" 순서로 보여야 한다
- 해결 문제: sortByWeight가 상태를 날짜보다 우선해 kium-11이 11.16 / 12.14 / 10.19 순으로 렌더
- 성공한 모습: 9과정 전건의 회차가 날짜 오름차순, closed만 뒤
```

### 2-4. 대안 검토 — 「보기 이동」 방식

원 제안에 이어 **"해당 과정의 공개교육 필터 상태 화면으로 이동"** 이라는 대안이 함께 제시되었다.

| | 경로 A — 인라인 | 경로 B — 보기 이동 |
|---|---|---|
| 화면 | 바뀌지 않음 | 카탈로그 19 → 9 · 필터·스트립 등장 |
| 읽던 맥락 | 유지 | **끊김** |
| 구현 비용 | 렌더 조건 1건 | **0 — 이미 존재** |

**★ 경로 B는 이미 구현되어 있다.** 카드의 `공개교육` 아웃라인 뱃지(`.kium-openflag` · `onOpenBadge()`)가
보기를 전환하고 카드 위치까지 복원한다. 그런데도 단절이 느껴진 이유는 **뱃지가 카드 썸네일 좌상단에
절대 배치**돼 있어, 상세 패널을 읽으려 스크롤하면 **화면 위로 벗어나기 때문**이다.

> 문제는 "이동 경로가 없다"가 아니라 **"상세를 읽는 동안 어떤 경로도 손 닿는 곳에 없다"** 이다.

**확정** — 두 경로는 배타적이지 않고 **사용자의 인지 상태**로 갈린다.

| 상태 | 원하는 것 | 경로 |
|---|---|---|
| 카탈로그 훑는 중 | **여러 과정** 일정 비교 | 경로 B — 카드 뱃지 (**현행 유지**) |
| 상세를 연 상태 | **이 과정** 일정 확인 후 신청 | 경로 A — 인라인 (**신설 = F17**) |

상세 패널에 이동 트리거를 **병설하지 않는다** — 같은 자리에서 회차를 볼 수 있는데
이동 링크를 함께 두면 선택지만 늘고 결정이 늦어진다.

### F17 — 상세 패널 인라인 회차 블록 (Must)

| 항목 | 내용 |
|------|------|
| **대상** | 과정안내 탭 · **전체과정 보기**의 상세 패널 · **공개교육 9과정 한정** |
| **위치** | 교육구성 표(⑥)와 CTA(⑦) **사이** |
| **제목** | `공개교육 일정` |
| **내용** | 해당 과정의 회차 카드 전건(1~3장) — 날짜 · 일수 · 상태·CTA 통합 버튼 |
| **동작** | 회차 CTA 클릭 → **보기 전환 없이** 상담 폼 이동 · 프리필 **경로 A**(회차 지정) |
| **위탁 10과정** | 블록 **미렌더** (`'-'` 표기 금지 — 기존 원칙 승계) |

**위치 근거**
전체 보기 상세 패널의 주제는 **"이 과정이 무엇인가"**다. 회차는 결정을 돕는 부가 정보다.
최상단(`variant="open"`의 위치)에 두면 과정 소개보다 일정이 먼저 나와 축이 뒤집힌다.
사용자의 인지 순서 `이 과정 알겠다 → 그럼 언제 하지? → 신청`에 맞춰 **결정 직전**에 배치한다.

**제목 근거**
`교육일정`으로 쓰면 이 과정 전체의 일정으로 읽힌다 — 실제로는 공개교육 회차만이고
이 과정들은 기업 위탁으로도 운영된다(`schedule: '연중상시'`). BT-08에서 pill 라벨을
`교육 일정` → `공개교육`으로 바꾼 것과 같은 근거다.

**성공한 모습 (Done when)**
- 전체 보기에서 `kium-14` 카드를 열면 CTA 바로 위에 `공개교육 일정` + 회차 카드 1장이 보인다
- 그 카드의 `상담하기`를 누르면 세그먼트가 `전체과정`인 채로 상담 폼에 도달하고,
  문의 내용에 `· 희망 회차: 12.11(금) · 1일 (개강확정)`이 담겨 있다
- 위탁 과정(`kium-01`)을 열면 이 블록이 DOM에 없다

### F18 — 메타 pill 요약화 (Must)

| 항목 | 현행 | 변경 |
|------|------|------|
| `공개교육` pill | `10.12(월) ~ 13(화), 11.2(월) ~ 3(화) 외 1건` | **`3개 회차`** |
| `교육비` pill | `400,000원` + `1인 기준` | **무변경** |

**근거**
pill의 역할은 메타 영역에서 **"이 과정은 공개교육으로도 됩니다"라는 사실**을 알리는 것이고,
날짜라는 **값**은 F17 블록이 진다. 같은 패널에 같은 날짜가 두 번 나오면 두 번째는 잡음이다.
`교육비`는 회차 카드에 없는 정보라 유지한다.

**성공한 모습**
- 상세 패널 안에서 회차 날짜 문자열이 **블록에만** 존재한다(pill 0건)
- pill이 `공개교육 3개 회차` 형태로 렌더된다

### F19 — CTA 분기 기준 전환 (Should)

| 과정 유형 | CTA 문구 | 프리필 | 비고 |
|-----------|----------|--------|------|
| 공개교육 9과정 | `이 과정으로 상담하기` | **경로 B** (`· 희망 회차: 협의 희망`) | 두 보기에서 동일 |
| 위탁 10과정 | `이 과정으로 신청 문의` | 경로 ① (`[관심 과정: …]`) | 현행 유지 |

**근거**
현행은 `variant`(보고 있는 화면)로 분기해, **같은 과정인데 화면에 따라 신청 경로가 달라진다.**
CTA가 가리키는 것은 보기가 아니라 **그 과정의 신청 방식**이다.
분기 기준을 `과정 성격`으로 바꾸면 두 보기의 CTA가 일치한다.

**중복이 아닌 이유** — 블록의 회차 CTA와 하단 CTA는 **의도가 갈린다**.

| 요소 | 의도 | 프리필 |
|------|------|--------|
| 회차 카드 `상담하기` | "이 날짜로 하겠다" | 경로 A (회차 지정) |
| 하단 `이 과정으로 상담하기` | "관심 있는데 일정은 협의" | 경로 B |

**성공한 모습**
- `kium-14`를 전체 보기 / 공개교육 보기 어느 쪽에서 열어도 하단 CTA 문구와 프리필이 동일하다
- `kium-01`(위탁)의 하단 CTA는 현행 그대로다

### F20 — 상세 패널 회차 날짜 정렬 (Must)

| 항목 | 내용 |
|------|------|
| **대상** | `SessionStrip` — **두 변형 공통**(전체 보기 · 공개교육 보기) |
| **규칙** | 1차 `closed` 뒤로 → 2차 시작일 오름차순 (「전체 일정」 리스트의 BT-26과 동일) |

**결함 실측**

| 과정 | 현행 | 기대 |
|------|------|------|
| `kium-11` AI 직무전문화 | **11.16 · 12.14 · 10.19** | 10.19 · 11.16 · 12.14 |
| `kium-10` 업무효율화: Data | **10.14 · 12.07 · 11.09** | 10.14 · 11.09 · 12.07 |

**근거**
`sortByWeight`는 weight ASC → start ASC이고 weight가 `confirmed 1 · closing 1 · recruiting 2 · closed 4`라
**상태가 날짜를 이긴다.** 전건 `recruiting`이던 동안에는 결과적으로 날짜순이었으나 상태 시드 적용 후 드러났다.
한 과정의 회차를 보는 과업은 "이 과정 언제 하지?"이므로 시간 축이 1순위다.

**F17과의 관계** — F17이 이 스트립을 전체 보기에도 노출시키므로, 고치지 않으면 결함이 두 배로 드러난다.
`variant="open"` 쪽도 같은 결함이 있었으므로 **양쪽 동일 개선**이며, 이는 §7-1 S6(open 무변경)의 예외로 명시한다.

**성공한 모습**
- 9과정 전건의 상세 패널 회차가 날짜 오름차순으로 렌더
- 전체 보기와 공개교육 보기에서 같은 과정의 회차 순서가 동일

## 6. 엣지 케이스 및 제약

### 6-1. 엣지 케이스

| # | 상황 | 처리 |
|---|------|------|
| E1 | 위탁 10과정 | 블록 미렌더. `'-'`·`미개설` 등 대체 표기 금지 |
| E2 | 회차 1건 | `.is-single` — PC 최대 320px, MO 전폭·스크롤 없음 |
| E3 | 회차 전건 마감(`closed`) | 기존 `SessionStrip` 처리 승계. 하단 CTA(경로 B)가 대안 |
| E4 | 회차 0건 (데이터 이상) | `isOpenCourse()`가 false가 되므로 E1과 동일 경로 |
| E5 | 딥링크 진입(`?consult=1&course=…&session=…`) | 기존 프리필 로직 무변경 — 패널이 열린 상태로 도착 |
| E6 | `?preview=badges` 쇼케이스 | 무변경 |

### 6-2. 유지되는 핵심 제약 (재확인)

| # | 제약 | 본 증분에서의 준수 |
|---|------|--------------------|
| C1 | **백엔드 없음** — 신청은 LMS 연동이 아닌 메일 폼 | 프리필 경로만 사용, 신규 통신 0 |
| C2 | **A/B 변인 통제** — 회차 UI는 A type 무변경 재사용 | `SessionStrip`·`SessionCard` 스타일 재정의 0 |
| C3 | **전체 보기 상시 노출 영역에 회차 요소 미생성** | 층위 재정의 — 그리드·카드·필터는 유지, **펼친 패널 안은 예외** |
| C4 | **교육비는 공개교육 9과정 1인 단가(N열)만** | 무변경. O열 총액 계열 숫자 0건 |
| C5 | **신규 색 토큰·신규 컴포넌트 발명 금지** | 기존 컴포넌트 재사용 + 옵션 prop |
| C6 | **SSG** — 서버 렌더 경로에서 `new Date()`·`window` 금지 | `now` null-safe 전달 승계 |

**C3 재정의 근거** — 이 제약의 목적은 *"카탈로그를 훑을 때 일정이 시끄럽게 끼어들지 않게"* 였다.
상세 패널은 사용자가 **직접 연** 영역이고 그리드에 상시 노출되지 않으므로 목적을 해치지 않는다.
검증 스위트 `D3`의 측정 대상(`.kium-ustrip`·`.kium-modehead`·`.kium-next`·필터 행)에
`.kium-strip`은 포함되지 않아 **기존 단언은 그대로 통과한다.**

## 7. 성공 기준

### 7-1. 기능적

| # | 기준 |
|---|------|
| S1 | 전체 보기 상세 패널(공개교육 9과정)에 `공개교육 일정` 블록이 CTA 바로 위에 렌더 |
| S2 | 위탁 10과정 상세 패널에 블록 미렌더 |
| S3 | 회차 CTA → 보기 전환 없이 상담 폼 이동 · 프리필에 `· 희망 회차:` 포함 |
| S4 | `공개교육` pill 날짜 나열 0건 · `N개 회차` 형태 |
| S5 | 하단 CTA가 과정 성격으로 분기 · 두 보기에서 동일 |
| S6 | `variant="open"` 상세 패널 **레이아웃·문구** 무변경 (블록 위치 · 제목 · pill 구성) — 정렬은 F20으로 양쪽 동일 개선 |
| S7 | 320/375/768/1024/1440 × 회차 1·2·3건 — 가로 넘침 0px · 44px 미만 타깃 0 |
| S8 | 기존 회귀 스위트 전건 통과(`D3` 포함) |
| S9 | 상세 패널 회차 날짜 오름차순 — `kium-11` `10.19 · 11.16 · 12.14` / `kium-10` `10.14 · 11.09 · 12.07` |
| S10 | 카드 `공개교육` 뱃지(보조 경로) 현행 유지 · 상세 패널에 이동 트리거 병설 0건 |

### 7-2. 비즈니스 (가설 · 측정)

| # | 가설 | 측정 |
|---|------|------|
| B1 | 전체 보기에서 발생한 상담 문의 중 **회차 지정 비율**이 0% → 유의미하게 상승 | 프리필 헤드 유형 분포(`[공개교육 상담 신청]` vs `[관심 과정:]`) |

| B3 | 영업 응대 품질 균일화 — 어느 화면에서 왔든 회차가 담긴 문의 수신 | 정성 — 담당자 회신 |

## 10. 정의 및 용어

| 용어 | 정의 |
|------|------|
| **전체과정 보기 / 공개교육 보기** | 과정안내 탭의 세그먼트 토글 두 상태. 전자는 19과정, 후자는 9과정 + 일정 영역 |
