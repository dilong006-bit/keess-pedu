## 1. 제안 해석

사용자 제안을 설계 언어로 재구성한다.

> **전체과정 보기에서 과정 상세를 연 사용자가, 보기를 전환하지 않고 그 자리에서
> 공개교육 회차를 확인하고 회차를 지정해 상담 신청까지 끝낼 수 있어야 한다.**

현재는 상세 패널이 **정보만** 준다 — `공개교육` pill에 날짜가 나열되고 `교육비` pill이 단가를 말한다.
그런데 **그 정보로 할 수 있는 행동이 없다.**

---

## 2. 진단 — 전환 깔때기에서 가장 뜨거운 지점에 벽이 있다

### 2-1. 현재 여정

| 단계 | 화면 | 상태 |
| --- | --- | --- |
| 1 | 카탈로그 19개 훑기 | 탐색 |
| 2 | 관심 과정 카드 클릭 → 상세 패널 확장 | **관심 확정** |
| 3 | 상세 읽기 → `공개교육 10.12~13` · `교육비 400,000원` 확인 | **신청 의향 최고점** |
| 4 | 신청하려면? | **경로 없음** |

4단계의 CTA는 `이 과정으로 신청 문의`이고, 프리필 **경로 ①**(`[관심 과정: …]`)로 간다.
**사용자가 방금 읽은 `10.12~13`이 상담 폼에 전달되지 않는다.**

### 2-2. 되짚기 비용

공개교육으로 신청하려면 사용자가 되돌아가야 한다.

| # | 행동 | 비용 |
| --- | --- | --- |
| ① | 상단으로 스크롤 | 스크롤 왕복 1 |
| ② | 세그먼트 `공개교육` 클릭 | 클릭 1 |
| ③ | 분야 필터가 걸려 있었다면 재적용 | 클릭 1~2 |
| ④ | 그 과정을 다시 찾아 카드 클릭 | 스크롤 왕복 1 + 클릭 1 |
| ⑤ | 회차 선택 | 클릭 1 |

**클릭 4~5회 + 스크롤 왕복 2회.** 그것도 이미 "이 과정 하겠다"고 마음먹은 사용자에게.

> 되짚기는 단순한 불편이 아니다. 3단계에서 확정된 **의사결정 맥락이 그 과정에서 흩어진다.**
> 상단으로 올라가면 다른 필터·다른 과정이 시야에 들어오고, 돌아왔을 때 처음의 확신이 남아 있지 않다.

### 2-3. ★ B안의 핵심 논거가 실제로는 성립하지 않고 있다

A/B 비교 자료에서 B안의 강점으로 제시한 문장이다.

> "19과정을 한 화면에서 보며 개설 과정에 표시가 붙습니다.
> **과정 선택과 신청 방식 선택을 한자리에서 합니다.**"

그런데 현재 구현은 **정보만 한 자리이고 행동은 다른 자리**다.
「신청 방식 선택」이 실제로는 보기 전환을 요구한다.

**이 제안은 새 기능 추가가 아니라 B안의 미완성 부분을 완성하는 일이다.**
9/7 HRD솔루션팀 택1 검토 전에 반영되면 B안의 설득력도 함께 올라간다.

## 3. 실현 비용 — 새로 만들 것이 거의 없다

| 자산 | 상태 |
| --- | --- |
| `SessionStrip` (상세 패널 회차 스트립) | **존재** — `variant="open"`에서 이미 동작 |
| `SessionCard` + `SessionAction` (상태·CTA 통합 버튼) | **존재** |
| 프리필 경로 A (회차 지정 · `consultSession()`) | **존재** |
| `onConsultSession` prop 전달 경로 | **이미 `default` 변형에도 전달 중** — `KiumCoursesTab` → `KiumCourseGrid` → `KiumCoursePanel` |
| 반응형 규칙 (`.kium-strip` 가로 배열 ↔ 스크롤+peek) | **존재** |

`KiumCoursePanel`의 `{isOpenVar && <SessionStrip … />}` — **이 렌더 조건 하나가 유일한 장벽**이다.
배선이 이미 끝나 있다는 것은, 이 단절이 설계 의도가 아니라 **`variant` 분기의 부작용**이었음을 뜻한다.

## 4. 그대로 열면 안 되는 것 — 4가지 조정

### 조정 1. 위치가 달라야 한다

| 변형 | 위치 | 근거 |
| --- | --- | --- |
| `open` (공개교육 보기) | 헤더 바로 아래 — 정보 순서 **①** | 공개교육 탭 맥락이므로 "언제 열리는지"가 첫 화면 |
| **`default` (전체 보기)** | **CTA 바로 위 — 정보 순서 ⑥과 ⑦ 사이** | 이 패널의 주제는 **"이 과정이 무엇인가"**다 |

전체 보기의 상세 패널을 최상단에 회차로 열면 **과정 소개보다 일정이 먼저 나와 축이 뒤집힌다.**
사용자의 인지 순서는 `이 과정 알겠다 → 그럼 언제 하지? → 신청`이므로 **결정 직전**이 자연스럽다.

### 조정 2. pill의 날짜 나열을 걷는다

현행 `공개교육` pill: `10.12(월) ~ 13(화), 11.2(월) ~ 3(화) 외 1건`
회차 블록이 들어오면 **같은 날짜가 한 패널에 두 번** 나온다.

→ pill을 **`공개교육 · 3개 회차`**로 축약한다.
pill의 역할은 메타 영역에서 **"이 과정은 공개교육으로도 됩니다"라는 사실**을 알리는 것이고,
날짜라는 **값**은 아래 블록이 진다. `교육비` pill은 유지한다(스트립 카드에 가격이 없다).

### 조정 3. CTA 분기 기준을 `보기`에서 `과정 성격`으로 바꾼다

현행: `isOpenVar ? 경로B : 경로①`
→ 같은 과정인데 **보고 있는 화면에 따라 신청 경로가 달라진다.**

| 과정 | CTA | 프리필 | 근거 |
| --- | --- | --- | --- |
| 공개교육 9과정 | `이 과정으로 상담하기` | 경로 B (`· 희망 회차: 협의 희망`) | 회차 중 맞는 게 없을 때의 대안 |
| 위탁 10과정 | `이 과정으로 신청 문의` | 경로 ① (`[관심 과정: …]`) | 현행 유지 |

**CTA가 가리키는 것은 보기가 아니라 그 과정의 신청 방식이다.**
기준을 `isOpenCourse(course.id)`로 바꾸면 같은 과정의 CTA가 두 보기에서 동일해진다.

블록의 회차 CTA와 하단 CTA는 중복이 아니다 — **의도가 갈린다.**

| | 의도 |
| --- | --- |
| 회차 카드 `상담하기` | "이 날짜로 하겠다" (경로 A · 회차 지정) |
| 하단 `이 과정으로 상담하기` | "관심 있는데 일정은 협의" (경로 B) |

### 조정 4. 블록 제목은 `공개교육 일정`

`open` 변형의 제목은 `교육일정`이다. 전체 보기에 그대로 쓰면 **이 과정 전체의 일정으로 읽힌다** —
실제로는 공개교육 회차만이고, 이 과정들은 기업 위탁으로도 운영된다(`schedule: '연중상시'`).
BT-08에서 pill 라벨을 `교육 일정` → `공개교육`으로 바꾼 것과 같은 근거다.

→ `SessionStrip`에 `heading` **옵션 prop**. 미지정 시 `교육일정`(open 변형 무변경).

### 조정 5. 상세 패널 회차 정렬을 날짜 오름차순으로

`SessionStrip`은 `sortByWeight`(weight ASC → start ASC)를 쓴다. weight는 `confirmed 1 · closing 1 · recruiting 2 · closed 4`라 **상태가 날짜를 이긴다.**

| 과정 | 현행 렌더 순서 | 기대 |
| --- | --- | --- |
| `kium-11` AI 직무전문화 | **11.16 · 12.14 · 10.19** | 10.19 · 11.16 · 12.14 |
| `kium-10` 업무효율화: Data | **10.14 · 12.07 · 11.09** | 10.14 · 11.09 · 12.07 |

한 과정의 회차를 보는 과업은 **"이 과정 언제 하지?"** 다. 시간 축이 축이다.
전건 `recruiting`이던 동안에는 결과적으로 날짜순이었으나 상태 시드 적용 후 드러났다.

**이 블록을 전체 보기에도 노출시키는 것이 본 제안이므로, 고치지 않으면 결함이 두 배로 드러난다.**
「전체 일정」 리스트에 적용한 BT-26과 같은 규칙(`closed` 뒤로 · 나머지 날짜 오름차순)을 쓴다.

## 5. 불변식 재정의 — "전체 보기에 회차 요소 미생성"과 충돌하는가

B type 명세의 절대 규칙이었다.

> "전체 보기에서는 회차 관련 요소 전부 DOM 미생성"

**충돌하지 않는다.** 규칙을 정확히 재정의한다.

| 층위 | 규칙 |
| --- | --- |
| **상시 노출 영역** — 카드 그리드 · 카드 내부 · 상단 필터 행 · 모드 헤더 · 일정 스트립 | 회차 요소 **미생성** (현행 유지) |
| **사용자가 명시적으로 펼친 상세 패널 안** | **예외 — 허용** |

이 규칙의 **목적**은 *"카탈로그를 훑을 때 일정이 시끄럽게 끼어들지 않게"* 였다.
상세 패널은 사용자가 **직접 연** 영역이고 그리드에 상시 노출되지 않으므로 목적을 해치지 않는다.

검증 스위트 `D3`가 측정하는 대상도 `.kium-ustrip` · `.kium-modehead` · `.kium-next` · 필터 행이며
**`.kium-strip`(상세 패널)은 포함되지 않는다** — 기존 단언은 그대로 통과한다.

## 6. 반응형 전략

`.kium-strip`의 기존 규칙을 그대로 승계한다. **신규 반응형 규칙을 만들지 않는다.**

| 뷰포트 | 배치 | 규칙 |
| --- | --- | --- |
| PC / TB | 회차 수만큼 가로 배열 | `grid-auto-flow:column; grid-auto-columns:minmax(210px,1fr)` |
| 회차 1건 | 과도한 확장 방지 | `.is-single{grid-auto-columns:minmax(210px,320px)}` |
| MO | 가로 스크롤 + peek + snap | `grid-auto-columns:82%; overflow-x:auto` |
| MO · 1건 | 전폭 · 스크롤 없음 | `.is-single{grid-auto-columns:100%;overflow-x:visible}` |
| reduced-motion | snap 무효화 | `.kium-strip{scroll-snap-type:none}` |

**부하 검토** — 공개교육 9과정의 회차 수는 **최대 3 · 최소 1**이다.
PC에서 3열은 패널 폭에 여유가 있고, MO에서는 3장 중 1.2장이 보이는 peek로 "뒤에 더 있다"가 전달된다.

**모바일에서 패널이 길어지는 문제** — 블록이 CTA 바로 위(조정 1)라 **스크롤 끝에서 만난다.**
읽기를 마친 지점에 결정 수단이 놓이므로 오히려 순서가 맞는다.

## 8. 두 경로 비교 — 인라인 vs 보기 이동

제안된 두 방향을 정면으로 비교한다.

| | **경로 A — 인라인** | **경로 B — 보기 이동** |
| --- | --- | --- |
| 동작 | 상세 패널 안에 회차 블록을 편다 | 트리거 클릭 → 공개교육 보기로 전환 + 그 과정으로 포커스 |
| 화면 | **바뀌지 않는다** | 카탈로그 19 → 9 · 필터 행 등장 · 일정 스트립 등장 |
| 읽던 맥락 | 유지 | **끊긴다** |
| 돌아오기 | 불필요 | 세그먼트 재전환 필요 |
| 구현 비용 | 렌더 조건 1건 | **0 — 이미 구현되어 있다** |

### 8-1. ★ 경로 B는 이미 존재한다

카드의 `공개교육` 아웃라인 뱃지(`.kium-openflag`)가 정확히 그 동작을 한다 —
클릭 시 `onOpenBadge()`가 **카드의 화면 높이를 기억했다가 보기를 전환하고 위치를 복원**한다.

```
.kium-openflag{position:absolute;top:10px;left:10px;…}
```

**그런데도 단절이 느껴진 이유** — 뱃지는 **카드 썸네일 좌상단**에 절대 배치돼 있고,
상세 패널은 그 아래(또는 행 뒤 전폭 슬롯)로 펼쳐진다.
패널을 읽으려 스크롤하면 **뱃지는 화면 위로 벗어난다.**

> 문제는 "이동 경로가 없다"가 아니라
> **"상세를 읽는 동안 어떤 경로도 손 닿는 곳에 없다"** 이다.

### 8-2. 두 경로는 배타적이지 않다 — 인지 상태가 갈린다

| 사용자 상태 | 원하는 것 | 맞는 경로 |
| --- | --- | --- |
| 카탈로그를 훑는 중 | **여러 과정**의 일정을 비교하고 싶다 | **경로 B** — 카드 뱃지 (이미 있음) |
| 상세를 연 상태 | **이 과정**의 일정을 보고 신청하겠다 | **경로 A** — 인라인 (신설) |

상세 패널을 연 사용자는 **"이 과정"에 집중한 상태**다.
여기서 화면 전체를 바꾸면 9과정 카탈로그 + 필터 + 스트립이 한꺼번에 들어오는데,
그건 **"과정을 고르는" 화면**이지 "이 과정을 신청하는" 화면이 아니다.
**이미 고른 사람에게 다시 고르는 화면을 주는 셈이다.**

### 8-3. 확정

> **주 경로 = 인라인(신설) · 보조 경로 = 카드 뱃지(현행 유지).**
> 두 경로가 사용자의 인지 상태에 따라 자연스럽게 갈린다. 상세 패널에 이동 트리거를 **추가하지 않는다** —
> 같은 자리에서 회차를 볼 수 있는데 이동 링크를 함께 두면 선택지만 늘고 결정이 늦어진다.

### 8-4. 그 밖에 검토했으나 채택하지 않는 것

| # | 대안 | 판정 |

| N1 | pill hover 시 회차 툴팁 | **기각.** 터치 기기에서 발화하지 않고, 툴팁 안에 인터랙티브 CTA를 두면 접근성이 깨진다 |
